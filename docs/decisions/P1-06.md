# P1-06 decisions: model and training loop (synthetic data only)

Code: `src/landslide/{model,train,predict}.py`; tests: `tests/test_{model,train,predict}.py`. Gate G3: nothing in
this task reads `patches.npy`, `meta.csv` or anything under `data/`. Every test and measurement below used random
tensors, a synthetic meta table and a fake state dict (a randomly initialised resnet18's).

## D20 · Per-step learning-rate schedule

- **Decision.** The LR is set before every optimiser step. With S steps per epoch, W = `warmup_epochs` × S and
  T = `max_epochs` × S, step t (0-based) counts τ = t + 1 and uses
  `lr = base·τ/W` for τ ≤ W and `lr = base·(1 + cos(π(τ − W)/(T − W)))/2` for τ > W.
  So the first step uses base/W, the last warm-up step (end of epoch 2) uses the peak `lr` = 3e-4, the curve is
  continuous there, and the last step of epoch 40 uses exactly 0. `history.csv` records the LR of each epoch's last
  step. Early stopping or an epoch cap truncates the schedule; it never rescales it.
- **Why.** D20's default ("per-step LR, linear warm-up over 2 epochs, then cosine to 0 at epoch 40"); Appendix B
  `train.schedule`.
- **Alternatives.** τ = t (the first step at LR 0 instead of the last); a per-epoch schedule. Both are within the text;
  the difference is one step in about 2,000.
- **Evidence.** `test_lr_schedule_boundaries`: base/W at step 0, base/2 half-way through the warm-up, base at step
  W − 1, base/2 half-way through the cosine, 0 at step T − 1, strictly monotone in each phase [E].
- **Deviation?** No.

## D20 · drop_last

- **Decision.** Each epoch keeps ⌊n_train / 64⌋ whole batches of a fresh permutation; the remaining
  n_train mod 64 samples of that epoch's permutation are skipped (different ones each epoch). S = ⌊n_train / 64⌋.
- **Why.** D20 default; it keeps every BatchNorm batch at 64.
- **Deviation?** No.

## D20 · Normalisation statistics

- **Decision.** Per-channel mean and standard deviation (ddof 0) over every pixel of the unit's training rows only
  (inner-val and test rows excluded), computed in float64 in two passes (mean, then squared deviations) from the
  float16 values as stored and as the network sees them. They are written to `norm.json` (float64 JSON numbers) and
  applied in float32 as (x − mean) / std, on the GPU, per batch. A non-finite or zero std raises.
- **Why.** Appendix A §7 "per-channel mean and std from the run's training patches"; D20 excludes the inner-val rows.
- **Evidence.** `test_outputs_and_contract` checks `norm.json` against a numpy float64 computation over the
  training rows (rtol 1e-12) and that it differs from the train + inner-val statistics [E].
- **Deviation?** No.

## D20 · Early stopping and the best epoch

- **Decision.** After each epoch the inner-val ROC AUC of the 8-view TTA probabilities is compared with the best so
  far; only a strictly higher value is an improvement, so ties keep the earliest epoch. Training stops once
  `patience` (8) epochs have passed without improvement (best at epoch e → the last epoch is e + 8) or at
  `max_epochs` (40). A non-finite AUC never improves. With `restore_best` the best epoch's weights (parameters and
  BatchNorm buffers, copied to the CPU at the improvement) are loaded back before `best.pt` and the predictions are
  written; the inner-val AUC is recomputed from the restored weights and stored as `val_auc_recomputed` (a mismatch
  is logged).
- **Why.** Appendix A §7 and Appendix B `train.early_stopping`; D20 for ties.
- **Evidence.** `test_early_stopping_scripted` and `test_early_stopping_in_train_unit` (scripted AUCs 0.50, 0.80,
  0.80, 0.70, 0.79 with patience 3: best epoch 2, stop after epoch 5, `best.pt` equal to the weights seen at epoch 2
  and not to the last ones) [E].
- **Deviation?** No.

## Dxx-new · Unit selection (train / inner-val / test rows per run)

- **Decision.** `select_unit_rows(run, meta, splits)` returns positional row indices into `meta` (= into the patch
  array), sorted:
  - `a_f<k>`: test = non-background rows with `fold == k`; pool = non-background rows with `fold >= 0` and
    `fold != k` (flysch stage-1 patches of the other folds);
  - `b`: test = non-background rows with `group_b == "test"`; pool = non-background rows with `group_b == "train"`
    (flysch and non-flysch Zlínský/Moravskoslezský);
  - `s2`: pool = every row (all stage-1 matched patches plus the background sample); no test set.

  In every run, inner-val = the pool rows whose `block` is in `splits["inner_val"][run]`, train = the rest of the pool.
  Background rows (`source == "background"`) appear only in `s2`, where they follow the same block rule (a background
  patch in an inner-val block is an inner-val row). Blocks are compared as strings. The function refuses inconsistent
  inputs: a `meta.fold` whose block is not in that fold's `splits.folds_a` list, a `group_b` row whose block is not in
  the matching `splits.group_b` list, an inner-val block holding test rows, a block shared by the test set and the
  pool, or a train / inner-val / test set without both classes. `keep` (mask or indices) restricts all three sets; the
  runner can use it for the smoke subset (D24, P1-14's).
- **Why.** Appendix A §4 and §7 (Runs); PLAN.md §4.3 contracts; the brief's rule that the background sample is for
  the stage-2 model only. For `s2` the inner-val split is by block ("15 % of blocks as inner validation"), so early
  stopping sees the same mix (matched pairs plus unmatched background) the stage-2 model is trained for, and no block
  is both trained and validated on.
- **Alternatives.** For `s2`, keep every background patch in training and validate on matched patches only. Not
  chosen: it splits the background by source rather than by block, and validates on a task the stage-2 model is not
  used for.
- **Evidence.** `test_select_*` on a synthetic table of 14 blocks (10 flysch over 5 folds, 4 non-flysch) with
  background rows [E].
- **Deviation?** No.

## Dxx-new · Random numbers in training

- **Decision.** Per unit: `random.seed(seed)`, `np.random.seed(seed)` and `torch.manual_seed(seed)` (CPU and CUDA),
  as the card asks; the head's initial weights come from torch's CPU generator after that seed. The data order and
  augmentation come from one `numpy.random.default_rng(seed)`: each epoch draws `permutation(n_train)` and then one
  D4 index in 0..7 per sample (aligned with the permutation), on the CPU, and copies both to the GPU. No CUDA random
  numbers are used.
- **Why.** D02 allows `default_rng(seed)` where the method names the seed directly (Appendix A §7: seeds 0, 1, 2).
  CPU-side draws make the order independent of the GPU and of the CUDA RNG implementation.
- **Alternatives.** Separate registered streams (`SeedSequence([seed, id])`) for order and augmentation; it would
  need new `replication.streams` keys and gains nothing, since the draw order within one generator is fixed.
- **Deviation?** No.

## Dxx-new · Determinism

- **Decision.** Inside `deterministic_mode()`: `cudnn.deterministic = True`, `cudnn.benchmark = False`,
  `torch.use_deterministic_algorithms(True)` (errors, not warnings); the previous settings are restored afterwards.
  `CUBLAS_WORKSPACE_CONFIG` must be `:4096:8` (or `:16:8`); `ensure_cublas_workspace()` sets it if CUDA has not
  started yet and raises otherwise. The entry point (P1-14) should set it before importing torch; the constant is
  `landslide.train.CUBLAS_WORKSPACE_CONFIG`. TF32 settings are left at torch's defaults.
- **No op needed a replacement.** Every op of the forward and backward pass has a deterministic CUDA kernel in torch
  2.14.1: ResNet's `AdaptiveAvgPool2d((1, 1))` dispatches to `mean` (deterministic); a probe showed that a (2, 2)
  output would raise under deterministic mode, so the check is live. MaxPool2d backward and the `index_put_` of the
  per-sample D4 also pass.
- **Evidence.** [E] `test_two_runs_bit_identical`: two 1-epoch runs (32 px synthetic patches, CUDA) give identical
  `history.csv` (apart from seconds), predictions, `norm.json` and `best.pt` tensors, and seed 1 differs. A 3-epoch
  run at 150 × 150 px in two separate processes gave byte-identical `history.csv` (apart from seconds), `preds_val.csv`,
  `preds_test.csv` and identical `best.pt` tensors.
- **Deviation?** No.

## Dxx-new · bf16 autocast, with the head in float32

- **Decision.** Training and TTA run the network under `torch.autocast(dtype=torch.bfloat16)`. The single-logit head is
  a `Float32Linear` (an `nn.Linear` that disables autocast and runs in float32), so the logits are float32 dot
  products of the bf16 features. The loss is BCE-with-logits on float32 logits (mean over the batch).
- **Why.** Appendix B `train.amp` = "bf16 autocast". A bf16 logit has 8 significant bits, so AUC, the seed ensemble
  and the stage-2 NMS would otherwise rank heavily rounded scores (many exact ties). The head is one 512 → 1 layer;
  keeping it in float32 changes nothing else.
- **Alternatives.** Plain autocast (bf16 logits): the more literal reading, but it quantises every score. Float32
  inference: slower stage 2 and different numerics between training and validation.
- **Deviation?** No (an implementation detail of "bf16 autocast"), but listed for the freeze.

## Dxx-new · Model construction and ImageNet weights

- **Decision.** `torchvision.models.get_model(cfg.model.arch, weights=None)` (resnet18), then a strict
  `load_state_dict` of the local file, then conv1 → a `in_channels`-channel conv (same kernel, stride, padding, no
  bias) with weights `mean_rgb(W).repeat(C) × 3/C`, and fc → `Linear(512, 1)` with PyTorch's default initialisation.
  The weights enum is the one `cfg.model.init` names (`IMAGENET1K_V1`); the default file is torchvision's cache name
  for it under `paths.torch_home/hub/checkpoints/` (`resnet18-f37072fd.pth`), i.e. where P1-07's download with
  `TORCH_HOME = data/cache/torch` puts it. Loading never downloads (`torch.load(weights_only=True)` of a local path;
  a missing file raises), and if the file name carries torch.hub's hash prefix the file's sha256 must match it.
- **Why.** Appendix A §7 and Appendix B `model`; PLAN.md P1-06 and P1-07.
- **Evidence.** `test_conv1_init_formula`, `test_conv1_on_identical_channels_matches_rgb_conv` (C equal channels
  through the new conv1 give the RGB conv's response to 3 equal channels: the reason for 3/C),
  `test_other_layers_loaded_and_head_replaced`, `test_no_network_used`, `test_hub_hash_prefix_is_checked` [E].
- **Deviation?** No.

## Dxx-new · Optimiser details

- **Decision.** `torch.optim.AdamW(model.parameters(), lr, weight_decay=0.01)` with torch's defaults otherwise
  (betas 0.9/0.999, eps 1e-8, foreach implementation). Weight decay applies to every parameter, BatchNorm and biases
  included (one parameter group).
- **Why.** Appendix A §7 "AdamW (lr 3e-4, weight decay 0.01)" names no exclusions or other settings.
- **Alternatives.** Excluding norm and bias parameters from decay is common practice but not in the method.
- **Deviation?** No.

## Dxx-new · Monitoring fields

- **Decision.** `history.csv` columns: `epoch` (1-based), `lr` (the epoch's last step), `train_loss` (mean of the
  epoch's batch losses, i.e. running BCE over the augmented batches as trained), `train_auc` (AUC of the logits of
  those batches, computed before each batch's update, over the samples used that epoch), `val_loss` (mean BCE over the
  8 views and all inner-val rows, float64 from float32 logits), `val_auc` (AUC of the 8-view mean sigmoid), `seconds`
  (wall time of the epoch including validation). The file is rewritten after every epoch. AUCs use
  `sklearn.metrics.roc_auc_score` (ties count one half, equal to the rank-based AUC of P1-05).
- **Why.** Appendix A §7 "Monitoring"; PLAN.md §4.3.
- **Deviation?** No.

## Dxx-new · TTA

- **Decision.** `predict.tta_predict(model, x)`: in eval mode (the caller's mode is restored), each chunk of samples
  is normalised, expanded to its 8 D4 views view-major (`d4.t_all_views`) and run as one batch of 8 × chunk under the
  training autocast; the result is the mean over views of sigmoid(logit), in float64 on the CPU. Training uses chunks
  of `cfg.train.batch_size` samples; `DEFAULT_CHUNK` (64) applies when a caller gives none. The chunk size does not
  change the method, but cuDNN may choose different kernels for different batch shapes, so a caller should fix it.
- **Why.** Appendix A §7 "Prediction" and "8-view TTA"; stage 2 (P1-12) reuses the function with the s2 run's
  `norm.json` (`predict.Normaliser.from_json`).
- **Evidence.** `test_d4_invariant_input` (all 8 view logits equal; TTA = the single-view probability),
  `test_equals_mean_sigmoid_over_views`, `test_batching_does_not_change_results` [E].
- **Deviation?** No.

## Dxx-new · Run-directory outputs and unit life cycle

- **Decision.**
  - `train_unit` refuses to overwrite a unit that has `done.json` (`overwrite=True` forces it) and deletes the other
    known outputs of a previous partial attempt before starting.
  - `best.pt` is `{"state_dict", "unit", "run", "seed", "epoch", "val_auc", "config_hash", "arch", "in_channels"}`;
    `model.load_checkpoint(path, cfg)` rebuilds the model from it.
  - `preds_val.csv` and `preds_test.csv` come from the restored best weights. For `s2` (no test set)
    `preds_test.csv` is written with its header only, so every unit has the same files.
  - `done.json` has every §4.3 field plus `run`, `git_dirty` (tracked files only), `peak_gpu_reserved_gb`,
    `epochs_run`, `stop_reason` (early_stopping | max_epochs | epoch_limit), `saved_epoch`, `val_auc_recomputed`,
    `steps_per_epoch`, `batch_size`, `smoke`, `device`, `torch`, `finished`. `seconds` is the unit's wall time;
    `peak_gpu_mem_gb` is `torch.cuda.max_memory_allocated` in GiB since the start of the unit.
  - An exception writes `failed.json` (error, traceback, config hash, commit) and is re-raised for the runner to log.
  - JSON and CSV files are written to a temporary name and renamed, so a crash never leaves a half-written
    `done.json`.
- **Why.** PLAN.md §4.3 and the runner's resume rule (a unit with `done.json` is skipped).
- **Deviation?** No.

## Dxx-new · Interruption hook

- **Decision.** `should_stop()` (no arguments) is asked before the first epoch and after every epoch that does not
  end the unit. When it returns True, the unit stops at that epoch boundary, keeps `history.csv`, writes
  `interrupted.json` (epochs completed, seconds) and returns `{"status": "interrupted", ...}`; it writes no `done.json`,
  `best.pt` or predictions. A unit whose last epoch has run (early stop, `max_epochs` or the epoch cap) finishes its
  predictions and `done.json` without asking. A rerun starts the unit from scratch.
- **Why.** The overnight runner's wall-clock cap (Appendix A §11, PLAN.md P1-14) stops gracefully between epochs;
  an unfinished unit must count as missing.
- **Evidence.** `test_interruption_hook` [E].
- **Deviation?** No.

## Dxx-new · Smoke mode epoch cap

- **Decision.** With `Paths(smoke=True)`, `train_unit` runs at most `cfg.smoke.max_epochs` (2) epochs unless the
  caller passes `epoch_limit`. The LR schedule is still the 40-epoch one, so the smoke epochs are the first two epochs
  of the real schedule (warm-up only).
- **Why.** Appendix B `smoke.max_epochs`; a truncated real schedule tests the real code path.
- **Alternatives.** Compressing warm-up and cosine into 2 epochs: a different schedule from the one that will run.
- **Deviation?** No.

## Dxx-new · Data handling

- **Decision.** Patches come from an injectable source (`data`: an array in memory or a `.npy` path opened as a
  memory map; default `paths.patches_npy`), with `meta` and `splits` likewise. The array must be (N, C, px, px) with
  N = rows of meta. Training and inner-val rows are copied to the GPU as float16 in chunks of 128 rows, checking each
  chunk for non-finite values (including float16 overflow); test rows are copied after training, once the training
  tensors are freed. There is no DataLoader.
- **Why.** Appendix A §7 "Data handling"; 16 GB RAM (PLAN.md §3 rule 11).
- **Deviation?** No.

## Runtime measurements (synthetic, for the runtime estimate)

- [E] RTX 3060, torch 2.14.1+cu130, deterministic mode, 150 × 150 px, batch 64:
  - training step ≈ 47 ms (≈ 1,350 samples/s), per-sample D4 and normalisation included;
  - 8-view TTA ≈ 4,600 images/s (≈ 575 patches/s);
  - an epoch of 560 training + 80 inner-val patches: 0.53 s steady state (first epoch 1.5–4 s with CUDA warm-up);
    peak allocated 1.59 GiB, reserved 2.93 GiB. With 1,400 + 200 patches: 1.4 s/epoch, peak 1.87 GiB.
- [I] At the expected dataset size (PLAN.md §11), an (a) fold (~3,100 training, ~550 inner-val patches) takes
  ~3.5 s/epoch and the s2 model (~9,500 + ~1,700) ~10 s/epoch with ~5 GB peak, so the 21 units need at most ~1 h
  at 40 epochs each, less with early stopping. P1-17 measures the real numbers.
