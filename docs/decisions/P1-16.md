# P1-16 decisions: the config key batch and the pre-registration

This task's first half (no data build, no CNN): add in one batch the config keys that earlier tasks requested (O7),
make the code read them, and fold every decision into `PREREGISTRATION.md`. The orchestrator does the second half:
rebuilding every artefact under the final config, writing `configs/landslide.sha256`, setting `status` to FROZEN and
making the freeze commit.

- **Placement.**
  - `eval.bootstrap.secondary_unit` (P1-05, P1-11 and P1-13's spelling) would sit inside an Appendix B block, so the
    key is `replication.eval.secondary_bootstrap_unit`.
  - `runner.min_free_gpu_gb` and `runner.eval_reserve_min` (P1-14's spelling) likewise became

    the same block as the fetch script.
- **Types.** Whole numbers are JSON integers (150, 7, 15, 10), as in Appendix B (`min_free_disk_gb: 10`,
  `neg_min_dist_to_polygon_m: 150`). The code casts them to float, so every computed value is unchanged.
- **One duplication kept on purpose.** `sources.dtm.service` repeats the URL that starts Appendix B's prose
  `dtm.service`. The code reads only the `sources` key; `tests/test_config_appendix_b.py` checks that the two agree.
- **Constants kept, and why.**
  - Not method values:
    - `sheets.SNAP_TOL_CELLS` (float tolerance) and `sheets.FULL_SHEET` (the `poznamka` text, a data-schema
      literal);
    - `susceptibility.CLASS_LABELS` (raster tag text) and `fetch_zabaged.BRIEF_NAMES` (the brief's role names,
      labels written to `results/sources.json`);
    - `baselines.SLOPE_SUSC_FEATURES` / `TERRAIN_FEATURES` / `STAT_COLUMNS` (the `meta.csv` column vocabulary that
      validates the configured scorers);
    - `net.USER_AGENT`, `ALLOWED_HOSTS`, `MIN_INTERVAL_S` (the brief's request rules), check tolerances, figure
      colours and chunk sizes.
  - `stage2.LR_FEATURES` stays a constant. Appendix A §9 defines the stage-2 comparator separately from §10, and
    its four features equal those of `slope_susc_lr` in `replication.baselines.scorers`. Making stage 2 read the
    stage-1 scorer list would tie two definitions together; not done.
  - No constant was kept only as a test default. The lattice helpers (`snap_out`, `grid_from_corner`,
    `grid_from_transform`, `Grid`, `CornerGrid`) now take the origin as a required keyword. The tests read it
    from the config.

## Pre-registration (§7, §8)

- **Decision.** `PREREGISTRATION.md` §7 lists every decision of P1-01 … P1-14 and the orchestrator's, one row each,
  grouped by stage: data and provenance; labels and splits; sampling and patches; channels; model and training;
  baselines; stage 2; evaluation and verdict; runner; infrastructure. Before the rows it states:
  - what was established before training: provenance, every §5 count next to ours, the stage-1 and stage-2
    baselines next to the spike's, and the O5 overlap count;
  - the two §5-guided readings (O2, O8) and Mark's approvals;
  - the incidents.

  §8 states that there is no deviation from Appendix A or B. It explains why each §5-guided choice is a reading, and
  lists the six closest calls with the reason each is not a deviation. §9 has placeholders for the orchestrator.
- **Evidence.** The numbers are taken from the tracked results (`results/provenance.json`, `splits_summary.json`,
  `sampling_summary.json`, `dataset_summary.json`, `baselines.json`, `stage2_baselines.csv`), not from the decision
  files' prose.
