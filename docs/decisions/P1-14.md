# P1-14 decisions: overnight runner

Code: `src/landslide/{runner,preflight,winawake}.py`, `scripts/run_overnight.py`; tests: `tests/test_runner.py` with
the synthetic inputs of `tests/runner_synth.py` (and P1-13's `tests/eval_synth.py`). Nothing in this task read or
wrote the real data tree: every test builds `Paths(root=tmp_path)`, and no CNN saw a real patch (gate G3). The real
runs are P1-17 (smoke) and phase 2 (Mark).

    uv run python scripts/run_overnight.py --dry-run     # preflight only
    uv run python scripts/run_overnight.py --smoke       # P1-17, after the freeze; writes only under data/smoke/
    uv run python scripts/run_overnight.py               # phase 2 (Mark); re-run the same command to resume

## D24 · Smoke subset

- **Decision.** One generator, `config.rng_for(cfg, replication.seed, "smoke_subset")` (seed 2611, stream 8), draws
  without replacement:
  1. round-half-up(`smoke.patch_frac` × n) of the sorted unique `pair_id`s ≥ 0 (non-background rows); both members
     of each drawn pair are kept;
  2. then round-half-up(`smoke.patch_frac` × n) of the background rows, by sorted `id`.

  The subset is a boolean mask over the rows of `meta.csv`, passed to `train_unit(keep=...)` for every smoke unit, so
  each unit trains, validates and tests on its usual rows intersected with the subset. Rows with `pair_id` < 0 that
  are not background (none are expected) are excluded and counted. The run summary records the counts and the
  sha256 of the kept ids, so a rerun can be checked to use the same subset.
- **Why.** PLAN.md D24 ("5 % of `pair_id`s plus 5 % of the background, seeded"); the orchestrator named the stream.
  Drawing by pair keeps each positive with its slope-matched negative, so the subset stays matched.
- **Alternatives.** A stratified draw per fold or stratum (not in D24); 5 % of rows (would split pairs).
- **Evidence.** [E] `test_smoke_subset_rule`: 192 pairs and 64 background rows give 10 pairs and 3 background rows
  (9.6 and 3.2 rounded half up); whole pairs; an independent draw from the same stream reproduces it; another seed
  differs; `patch_frac` 1 keeps everything.
- **Deviation?** No.

## Dxx-new · Smoke mode

- **Decision.** `--smoke` runs the Appendix B `smoke` block: units `smoke.runs` (a_f0, b, s2) × `smoke.seeds` (0),
  `smoke.max_epochs` (2) epochs (`train_unit` caps them in smoke mode; the 40-epoch LR schedule is kept, P1-06), on
  the D24 subset. Stage 2 runs whatever (a) and (b) give, on the first `smoke.stage2_sheets` (1) of the 20 reserved
  sheets in sorted order (02-41-01, the rule of `scripts/stage2_baselines.py --smoke`). On that sheet the runner
  recomputes the four stage-2 baselines (`stage2.run_baselines`, CPU, seconds) and then the CNN scores, so the smoke
  evaluation has comparators. Everything goes through `Paths(smoke=True)`: run directories, stage-2 outputs, the
  evaluation's `results/` and `figures/`, the log and the run summary all land under `data/smoke/`. Inputs are only
  read.
- **Why.** BRIEF.md Phase 1 item 7; Appendix B `smoke`; PLAN.md D24 and P1-14 item 7.
- **Alternatives.** Reusing the full run's baseline detections for the smoke sheet: they were matched pooled over 20
  sheets, so their outcomes differ from a 1-sheet matching. Skipping the baselines in smoke: the smoke evaluation
  would then not exercise the comparator path.
- **Evidence.** [E] `test_smoke_mode_with_a_fake_backend` and `test_smoke_end_to_end_with_the_real_code` (real
  training on random 64 px patches, real stage 2 on a toy reserved sheet, real evaluation): every new or changed
  file is under `data/smoke/`; the tracked `results/`, `figures/` and `logs/` are untouched; stage 2 ran on one
  sheet although (a) failed.
- **Deviation?** No.

## Dxx-new · Freeze gate in code

- **Decision.** The preflight fails unless `configs/landslide.sha256` exists and equals `config_hash` of the config
  on disk (the hash leaves out `status`, O1). This applies to `--smoke` and `--dry-run` too. In a git checkout it
  also fails if `configs/landslide.json` or `configs/landslide.sha256` is untracked or has uncommitted changes
  (`git status --porcelain` on those two paths), and it records the last commit that touched the sha256 file as
  `freeze_commit`. A `status` that does not start with FROZEN is a warning only. Without git, or outside a checkout,
  the commit check is skipped with a warning.
- **Why.** Gate G3: no CNN trains before the freeze, the smoke test included; the order of commits on `phase-1` is
  the proof (PLAN.md §2 item 4), so training from an uncommitted freeze would break the proof.
- **Alternatives.** Checking only the sha256 file, as the card states (kept, plus the commit check); making the
  status a hard check (the sha256 file is the freeze's machine-readable record; `status` is prose).
- **Evidence.** [E] `test_preflight_failure_exits_within_60s_with_a_clear_message[missing_freeze]`,
  `test_missing_freeze_applies_to_smoke_too`, `test_preflight_config_must_equal_the_frozen_hash`,
  `test_preflight_requires_a_committed_freeze` (a temporary git repository: committed passes and records the
  commit; an uncommitted change fails), `test_real_script_refuses_before_the_freeze` (the real script in a fresh
  process, before any freeze: exit 2).
- **Deviation?** No.

## Dxx-new · Built artefacts must carry the frozen hash

- **Decision.** The preflight compares the frozen hash with the hash each built artefact records:
  `splits.json` (`config_hash`), `data/dataset/build_info.json`, `data/baselines/build_info.json`, and the stage-2
  baseline outputs: every row of `results/stage2_baselines.csv`, `data/stage2/summary.json` and the
  `config_hash` stored in each of the 20 `data/stage2/lattice/<sheet>.npz`. The per-scorer score files hold no hash;
  they are checked for presence. It also requires that the stage-1 baselines were built from the dataset's
  `meta.csv` (the sha256 that `data/baselines/build_info.json` records for it equals the one
  `data/dataset/build_info.json` records; a comparison of recorded hashes, no hashing), and that the CSV, the
  summary and `detections.parquet` all hold the four stage-2 baseline scorers (slope_only, susceptibility,
  slope_susc_lr, random). In smoke mode the stage-2 baseline outputs checked are the full run's (`data/stage2/`,
  `results/`).
- **Why.** The orchestrator's instruction; O7 (P1-16 re-runs every deterministic build under the final config), so a
  stale artefact is a missed rebuild. Appendix A §9: the stage-2 comparators are run in phase 1, and the full run
  evaluates the CNN next to them.
- **Evidence.** [E] `test_preflight_checks_the_artefact_hashes`.
- **Deviation?** No.

## Dxx-new · Preflight checks

- **Decision.** `preflight.run_preflight` runs every check and reports all problems at once (each check is guarded,
  so an unexpected error becomes a problem, not a crash):
  - **Files.** A required-files list: `splits.json`, `sheets.parquet`, `polygons.parquet`; `patches.npy`,
    `meta.csv`, `data/dataset/build_info.json`; `data/baselines/preds_{a,b}.csv` and `build_info.json`; the DTM and
    susceptibility rasters of the 20 reserved sheets; the stage-2 baseline outputs above (CSV, summary, detections,
    20 lattices, 4 × 20 score files); the ImageNet weights. Each must be a regular, non-empty file. Sizes are
    compared where they are recorded: `patches.npy` and `meta.csv` against `data/dataset/build_info.json`, the
    weights against `results/sources.json` (46,830,571 bytes). Nothing is hashed in full. Each group's problem names
    the script that builds it.
  - **Dataset.** The `.npy` header (read with `numpy.lib.format`, no data): float16, C order,
    (N, `len(channels)`, `patch.px`, `patch.px`); file size = header + data; N = rows of `meta.csv`, which must hold
    every column training, the evaluation, the smoke subset and the stage-2 LR read; `build_info.json` agrees on
    shape, bytes and rows.
  - **Stage-2 rasters.** `is_stage2` in `sheets.parquet` marks exactly the config's 20 sheets, and each DTM and
    susceptibility raster has the `grid_h` × `grid_w` that `sheets.parquet` records (rasterio header only).
  - **Machine.** Free disk on the drive of `data/` ≥ `runner.min_free_disk_gb`; CUDA available with ≥ 7 GiB free GPU
    memory. "GB" is read as GiB (2^30 bytes), the stricter reading; the 3060 shows about 11 GiB free.
  - **Config.** `runner.num_workers` must be 0 (there is no DataLoader to give workers to).
- **The 60 s budget.** The GPU probe (importing torch, starting CUDA, `torch.cuda.mem_get_info`) runs in a daemon
  thread with a timeout of whatever is left of 60 s since the runner started, less 8 s for the exit (at least 5 s),
  so a hung driver still ends the preflight in time. The weights path needs torch, so the weights check runs after
  the probe and is reported "not checked" if torch did not load. A preflight longer than 60 s adds a warning.
- **Why.** BRIEF.md Phase 1 item 6 ("Fail-fast", "Offline: it reads only cached data, and checks this at start-up");
  Appendix A §11; PLAN.md P1-14 item 2.
- **Alternatives.** Stopping at the first problem (one problem per attempt is slower to fix); hashing every input
  (minutes for 3.5 GB of patches; the card says no full hashing).
- **Evidence.** [E] The real script on an empty root: exit 2 after 5.8 s warm (22 s on the very first, cold start),
  measured in this task. Tests: a complete synthetic tree passes; the four card cases (missing file, low disk, no
  CUDA, missing freeze) each exit with code 2 in well under 60 s with the problem in the console and the log;
  dataset shape, padding, missing columns, raster sizes, weights size, low GPU memory, a hung probe (stopped by the
  timeout) and `num_workers` each give their message.
- **Deviation?** No. The 7 GiB and the 15 min reserve have no config key (see "Config keys" below).

## Dxx-new · Offline after the preflight

- **Decision.** After a passed preflight, `preflight.block_network()` patches `socket.socket.connect`,
  `connect_ex`, `sendto`, `socket.getaddrinfo`, `gethostbyname` and `gethostbyname_ex`: any connection, datagram or
  name lookup to a non-loopback address raises `NetworkBlocked` before a packet is sent (so `create_connection`,
  urllib3, requests and `landslide.net` all fail). Loopback (127.0.0.0/8, ::1, "localhost") stays allowed. The block
  lasts for the rest of the run and is undone on exit. `NetworkBlocked` is a `RuntimeError`, so library retry loops
  that catch `OSError` do not swallow or retry it.
- **Why.** Appendix A §11 ("Socket connections are then disabled for the rest of the run"); BRIEF.md "Offline".
- **Alternatives.** Blocking loopback too (P1-07's offline check does): Python's own `socket.socketpair` on Windows
  connects over loopback (asyncio and some libraries use it), so a library could crash for a reason unrelated to the
  network; loopback cannot leave the machine.
- **Evidence.** [E] `test_socket_block` (TEST-NET address, `.invalid` name, UDP, requests: all raise; a loopback
  connection and `socketpair` work; every function is restored afterwards); the runner tests assert the block is
  active inside every training and stage-2 call and gone after the run.
- **Deviation?** No.

## Dxx-new · Keeping Windows awake

- **Decision.** `winawake.keep_awake()` calls `kernel32.SetThreadExecutionState(ES_CONTINUOUS |
  ES_SYSTEM_REQUIRED)` (ctypes, DWORD signature) when the work starts and `SetThreadExecutionState(ES_CONTINUOUS)` in
  `finally`. No power plan or timeout is changed; the display may still turn off. A failed call (return 0) is logged
  and the run goes on. Off Windows it is a no-op. It wraps the work (not the preflight), on the main thread that does
  the work.
- **Why.** BRIEF.md Phase 1 item 6 "Awake"; PLAN.md P1-14 item 3.
- **Evidence.** [E] `test_keep_awake_*` (set then released even when the body raises; no-op off Windows; a failed
  call is not fatal; the real call on this machine succeeds and is released).
- **Deviation?** No.

## Dxx-new · Order of work and the stage-2 gate

- **Decision.** Run-major order: a_f0_s0, a_f0_s1, a_f0_s2, a_f1_s0, …, a_f4_s2, b_s0, b_s1, b_s2; then
  `evaluate.run_evaluation`; then, only if `evaluate.stage2_allowed(metrics)` ((a) and (b) both PASS): s2 × seeds,
  stage-2 CNN inference, the CNN's stage-2 evaluation, and `run_evaluation` again (the final verdict). Otherwise the
  s2 units are recorded as `not_run` with the reason, and the first evaluation is final (nothing changed since, and
  the evaluation is deterministic). A failed evaluation never allows stage 2.
- **Why.** Appendix A §1 and §11; PLAN.md P1-14 item 4; P1-13's notes for P1-14.
- **Evidence.** [E] `test_full_run_order_and_stage2_when_a_and_b_pass` (the exact call sequence; REPLICATED on
  synthetic predictions), `test_stage2_is_skipped_when_a_or_b_fails[a|b]` (no s2 unit, no stage-2 call, NOT
  REPLICATED with stage 2 NOT_RUN), `test_a_failing_evaluation_is_logged_and_never_allows_stage2`.
- **Deviation?** No.

## Dxx-new · Stage 2 in the full run

- **Decision.**
  - Inference runs only when every s2 seed is finished; otherwise it is skipped with the reason (stage 2 is then
    INCOMPLETE, never a smaller ensemble).
  - The s2 models are loaded once (`stage2.load_s2_models` with the run's seeds: `train.seeds`, or `smoke.seeds` in
    smoke mode, where only seed 0 exists). `stage2.run_cnn` is then called one sheet at a time, so the wall-clock cap
    is checked between sheets and an exception on one sheet is logged without losing the others; `run_cnn` itself
    skips sheets scored earlier (resume).
  - When every sheet is scored, `stage2.evaluate_scorers(cfg, paths, ["cnn"], write_results=False)` adds the CNN's
    detections to `detections.parquet` and `summary.json` next to the phase-1 baseline rows. `write_results=False`
    because the tracked `stage2_baselines.csv` holds baselines only.
  - The full run does not recompute the stage-2 baselines: they are phase-1 outputs (Appendix A §9 "run in phase
    1"), checked by the preflight; "stage-2 inference with baselines" (§11) is read as evaluating the CNN in the same
    pipeline and file as those baselines.
- **Evidence.** [E] `test_full_run_order_and_stage2_when_a_and_b_pass`; `test_cap_during_stage2_inference_is_incomplete`
  (6 of 20 sheets scored before the cap: no CNN evaluation, verdict INCOMPLETE); the end-to-end smoke test runs the
  real `run_cnn` and `evaluate_scorers`.
- **Deviation?** No.

## Dxx-new · Resume

- **Decision.** Per unit, at the moment the runner reaches it:
  - `done.json` present: skipped, never overwritten (`train_unit` refuses anyway). If its config hash is not the
    frozen one, or there are several status files, the runner logs it and records the problem; the unit stays and
    the evaluation counts it as missing (hash_mismatch / invalid), so the test is INCOMPLETE. Retraining over it
    would destroy the evidence; that is Mark's call.
  - `failed.json` or `interrupted.json` present, or only a `history.csv` (a run killed with Ctrl-C or a power cut):
    trained again from scratch in this invocation (`train_unit` deletes the old outputs and has no mid-unit resume).
    The previous status, error and epochs are logged (with the old traceback) and kept in the run summary under
    `previous_attempt`. Each unit gets at most one attempt per invocation, so a deterministic failure cannot loop.
  - Each invocation gets the full wall-clock cap from its own start.
  - `run_summary.json` is rewritten by each invocation and keeps a short record of the earlier ones
    (`previous_invocations`: start, end, status, verdict, commit).
- **Why.** Appendix A §11 ("A unit with done.json is skipped"); BRIEF.md "Resumable: re-running the command skips
  finished units"; the orchestrator asked to decide the failed / interrupted case. A failure may be transient (GPU
  out of memory, driver reset), and re-running the command is the documented way to resume, so retrying is the
  expected behaviour; a deterministic failure costs one quick attempt per invocation.
- **Alternatives.** Skipping failed units unless a `--retry-failed` flag is given: one more thing for Mark to know,
  and a resumed run would silently stay INCOMPLETE.
- **Evidence.** [E] `test_resume_skips_finished_units_and_retrains_failed_ones` (done units untouched byte for byte;
  failed, interrupted and status-less units retrained; a second invocation trains nothing, gives a byte-identical
  `metrics.json` and records the first invocation), `test_a_done_unit_with_another_hash_is_never_overwritten`.
- **Deviation?** No.

## Dxx-new · Robustness

- **Decision.** An exception in a unit is logged with its traceback (`log.exception`; `train_unit` has already
  written `failed.json`) and the runner moves on to the next unit. The same holds for a stage-2 sheet, the stage-2
  inputs or models, the smoke baselines and each evaluation. Missing units (missing, failed, interrupted,
  hash-mismatched or invalid in the final evaluation's integrity record) are listed in `missing_units` and in the
  log; they never pass (P1-13's INCOMPLETE). Ctrl-C ends the run at once: the current unit is recorded as
  `aborted`, the summary is written with status `aborted`, the network block and the keep-awake request are
  released, and the exit code is 130; the same command resumes.
- **Evidence.** [E] `test_one_failing_unit_does_not_stop_the_run` (all 18 stage-1 units attempted; the traceback is
  in the log; INCOMPLETE), `test_ctrl_c_writes_an_aborted_summary`.
- **Deviation?** No.

## Dxx-new · Wall-clock cap

- **Decision.** The cap is `runner.wall_clock_h` (6 h) or `--max-hours`, counted from the start of the runner
  (before the preflight). 15 min are kept for the evaluation: from `start + cap − 15 min` on, no unit and no
  stage-2 sheet starts, and a running unit stops at its next epoch boundary (`train_unit(should_stop=...)`, which
  writes `interrupted.json`, never `done.json`). Then the evaluation runs on what has finished, so the verdict is
  INCOMPLETE (or NOT REPLICATED if a completed test failed, D25); never REPLICATED. The summary's status is
  `stopped_at_cap` and `cap.reached` is true. A cap shorter than the reserve trains nothing.
- **Why.** Appendix A §11; BRIEF.md "Capped"; PLAN.md P1-14 item 5.
- **Alternatives.** Predicting whether the next epoch fits before starting it: unnecessary with a 15 min reserve
  (an epoch takes seconds).
- **Evidence.** [E] `test_wall_clock_cap_stops_cleanly_and_the_verdict_is_incomplete` (fake clock: two units done,
  the third interrupted after 1 epoch, the rest not started, INCOMPLETE), `test_cap_with_the_real_training_code`
  (the real `train_unit` stops after epoch 1 with `interrupted.json` and no `best.pt`; INCOMPLETE),
  `test_cap_shorter_than_the_evaluation_reserve_trains_nothing`, `test_cap_during_stage2_inference_is_incomplete`.
- **Deviation?** No.

## Dxx-new · Logging and `run_summary.json`

- **Decision.**
  - **Log.** `<Paths(smoke).logs>/overnight_<local YYYYmmdd_HHMMSS>.log` (`logs/` normally, `data/smoke/logs/` in smoke
    mode), through `landslide.logs` (progress bars on the console only), with Python warnings routed to it.
  - **Run summary.** `<Paths(smoke).results>/run_summary.json` (tracked `results/` normally), UTF-8, LF, rewritten
    atomically after every step so it shows progress. Paths in it are relative to the repository root. Schema
    (version 1):
    - `schema_version`, `smoke`, `status` (running, finished, stopped_at_cap, aborted, error), `started_utc`,
      `finished_utc`, `wall_seconds`;
    - `config_hash`, `frozen_hash`, `freeze_commit` (last commit touching `configs/landslide.sha256`), `git_commit`
      and `git_dirty` at the start, `log_file`;
    - `cap` {wall_clock_h, source (runner.wall_clock_h | --max-hours), eval_reserve_min, reached};
    - `preflight` {ok, seconds, problems, warnings, info (hashes, GPU, free disk, dataset shape, file counts)};
    - `plan`, `smoke_subset` (smoke only);
    - `units`: unit → {run, seed, status (done | skipped | failed | interrupted | not_started | not_run | aborted),
      seconds, best_epoch, best_val_auc, epochs_run, stop_reason, peak_gpu_mem_gb, error, epochs_completed,
      reason, previous_attempt, problem}, in execution order;
    - `evaluations`: [{when (after_stage1 | final), verdict, statuses, estimates, seconds, final} or {when, error}];
    - `stage2` {allowed, reason, cnn {status, seeds, sheets, seconds, n_windows_scored, windows_per_s, n_seeds,
      peak_gpu_mem_gb}, cnn_evaluation, baselines (smoke)};
    - `verdict`, `verdict_detail` (both from the final `metrics.json`), `missing_units`;
    - `measurements` (below), `previous_invocations`.
- **Exit codes.** 0 the run finished (whatever the verdict) or a dry run passed; 2 preflight failed (nothing trained,
  no summary written); 1 the runner itself failed or no evaluation could be made; 130 Ctrl-C.
- **Why.** PLAN.md P1-14 item 6 and §4.3; the card's fields (units with status and duration, config hash, git
  commit, freeze SHA, verdict, missing units).
- **Evidence.** [E] the runner tests read the summary after every scenario; `test_full_run_order_…` checks LF and
  that no absolute path is written.
- **Deviation?** No.

## Dxx-new · Measurements for P1-17's runtime estimate

- **Decision.** For every finished unit (both modes), `measurements.units.<unit>`: epochs, mean seconds per epoch,
  the first epoch's seconds (CUDA warm-up) and the mean of the later ones (`history.csv` `seconds`, which include the
  inner-val TTA), the unit's seconds, `peak_gpu_mem_gb` and `peak_gpu_reserved_gb` (`done.json`), n_train / n_val /
  n_test, steps per epoch and batch size. For stage 2, `measurements.stage2`: windows scored, windows per second
  (per sheet: channels, window assembly and TTA, as `run_cnn` times them), the number of seeds (1 in smoke, 3 in the
  full run) and the peak GPU memory of inference. In smoke mode also `full_unit_sizes` (n_train / n_val / n_test of
  all seven full-run units, from `train.select_unit_rows` without the subset) and `full_stage2` (the 20-sheet
  window count from `data/stage2/summary.json`), so the scale factors for the estimate are in one file.
- **Why.** The orchestrator's instruction; BRIEF.md Phase 1 item 7.
- **Evidence.** [E] `test_smoke_end_to_end_with_the_real_code` checks every field on a real (synthetic-data) smoke
  run.
- **Deviation?** No.

## Dxx-new · Entry point and environment

- **Decision.** `scripts/run_overnight.py` does its work under `if __name__ == "__main__":` and imports only
  `landslide.runner`, which imports no torch at module level. `runner.main()` sets `CUBLAS_WORKSPACE_CONFIG=:4096:8`
  (equal to `train.CUBLAS_WORKSPACE_CONFIG`, tested) and `TORCH_HOME = Paths().torch_home` first thing, before
  anything loads torch; it refuses to go on if CUDA had already started with a non-deterministic cuBLAS setting.
  Both are set unconditionally, so a stray user setting cannot change the run. Options: `--smoke`, `--dry-run`,
  `--max-hours`, `--no-progress`, and a hidden `--root` that points the runner at another repository root (used by
  the tests only). There is no DataLoader and no worker process.
- **Why.** PLAN.md P1-14 item 1; P1-06's determinism contract; BRIEF.md "Windows-safe".
- **Evidence.** [E] `test_runner_import_does_not_load_torch` (fresh process), `test_constants_match_the_modules`.
- **Deviation?** No.
