# P1-05 decisions: metrics and bootstrap

All code is in `src/landslide/metrics.py`; tests in `tests/test_metrics.py` (synthetic data only). Every value
(replicate count, seed, CI level, recall level) comes from the config or an explicit argument; nothing is hard-coded.

## Dxx-new · ROC AUC with ties

- **Decision.** `roc_auc(y, score, weights=None)` is the rank (Mann–Whitney) AUC with ties averaged: over all
  positive–negative pairs, 1 if the positive scores higher, 1/2 on a tie, 0 otherwise, divided by n_pos × n_neg. It
  is computed from the score tie groups (ascending): 2U = Σ_g P_g (2 C_g − N_g), with P_g and N_g the positive and
  negative weight in group g and C_g the cumulative negative weight up to and including g. With integer weights this
  is exact integer arithmetic until the final division. A one-class input, or a NaN or inf score, raises
  ValueError. Optional integer weights equal duplicating items.
- **Why.** Appendix A §8 asks for ROC AUC; the card asks for rank-based with ties averaged. This is algebraically the
  midrank formula (R_pos − n_pos(n_pos+1)/2)/(n_pos n_neg), and one code path serves both the point estimate and
  the vectorised bootstrap, so the two agree bit for bit.
- **Alternatives.** `sklearn.metrics.roc_auc_score` (same value, but too slow to call 2,000 times per scorer and
  not vectorisable over replicates); the explicit midrank formula (same value, floating-point rank sums).
- **Evidence.** [E] Equal to `roc_auc_score` and to the scipy midrank formula to 1e-12 on 15 random cases with and
  without heavy ties, and with integer sample weights; hand cases (1, 0, 0.5, 0.75, 5/6) exact.
- **Deviation?** No.

## Dxx-new · Cluster-bootstrap draws

- **Decision.** `draw_clusters(clusters, n_replicates, seed)`:
  1. The cluster labels of the items passed (sheet or block, any label array) are sorted with `np.unique`; K is the
     number of distinct labels among those items (for test (a), the flysch test sheets that hold a test patch).
  2. `np.random.default_rng(seed).integers(0, K, size=(B, K))`, one call; row b holds the K clusters drawn with
     replacement for replicate b. B and the seed come from `cfg["eval"]["bootstrap"]` (`n` = 2000, `seed` = 123)
     through `bootstrap_spec(cfg)` / `draw_clusters_from_cfg`.
  3. A replicate is the concatenation of every drawn cluster's items, so an item's multiplicity is the number of
     times its cluster was drawn. The replicate's size in items varies; its size in clusters is always K.
  4. The draws are made once per test set and unit (a `ClusterDraws` object) and shared by every scorer and
     statistic on those items. A fingerprint (`key`) is stored with every result so paired differences can check
     that they really share draws.
  5. Each call re-seeds with the configured seed, so the draws for one test set don't depend on what was evaluated
     before it.
  6. Predictions are held fixed; nothing is refitted per replicate.
- **Why.** Appendix A §8: "resample test sheets with replacement, 2,000 replicates, percentile 95 %, seed 123";
  "CNN − baseline uses the same resamples". D02: the method names the seed directly, so `default_rng(123)`.
  Sorting the labels makes the draws independent of row order (tested).
- **Speed.** The replicate AUCs are computed from the multiplicities, vectorised over chunks of replicates:
  for each scorer the items are sorted once, then for each chunk the item weights are gathered from the cluster
  counts and reduced per tie group. This equals the AUC of the explicitly concatenated resample exactly (tested
  replicate by replicate).
- **Alternatives.** `rng.choice(K, size=(B, K))` (equivalent in distribution but a different stream; we fix the
  `integers` call); stratifying the resample by class or by fold (not what Appendix A says); drawing separately per
  scorer (would break the pairing); a Python loop over explicit resamples (same values; slower: about 1.1 s per
  scorer with this module's `roc_auc`, about 7.9 s with sklearn's).
- **Evidence.** [E] 7,000 synthetic patches, 300 sheets, 2,000 replicates on this CPU: draws 0.015 s, one scorer
  0.43–0.51 s, four scorers plus three paired differences 1.14–1.17 s; a second run gave identical numbers.
- **Deviation?** No.

## D21 · Degenerate bootstrap replicate (one class)

- **Decision.** A replicate whose resample holds only positives or only negatives has no AUC. Its value is NaN; it
  is dropped from the CI and counted. Every result reports `n_replicates` (2,000 requested), `n_used` and
  `n_degenerate`. No replacement replicates are drawn.
- **Why.** The PLAN.md §6 default. Whether a replicate is degenerate depends only on the labels and the draws, not
  on the scores, so the same replicates are dropped for every scorer and the paired differences stay paired
  (checked in `paired_differences`).
- **Alternatives.** Redrawing until 2,000 valid replicates (changes the stream and complicates pairing); counting a
  degenerate replicate as 0.5 (biases the CI).
- **Evidence.** [I] With hundreds of test sheets and same-sheet slope matching, a one-class replicate is practically
  impossible in tests (a) and (b); the path matters for small subsets such as per-kraj breakdowns. [E] Tested with a
  constructed 3-sheet case where about a third of the replicates are one-class.
- **Deviation?** No.

## Dxx-new · Percentile CI and point estimate

- **Decision.** The point estimate is the statistic on the full test set (not the bootstrap mean or median). The CI
  is the (1 − ci)/2 and 1 − (1 − ci)/2 quantiles of the used replicates, `np.quantile(..., method="linear")`
  (numpy's default, Hyndman–Fan type 7). The two levels are rounded to 12 decimals, so ci = 0.95 uses exactly 0.025
  and 0.975 rather than the float 0.025000000000000022. With no used replicate the CI is NaN, NaN.
- **Why.** Appendix A §8 / Appendix B `"method": "percentile"`, `"ci": 0.95`. `bootstrap_spec` raises for any other
  method rather than silently doing something else.
- **Alternatives.** Other quantile definitions (`inverted_cdf`, i.e. plain order statistics; `hazen`;
  `median_unbiased`). [E] On 2,000 synthetic replicate AUCs they differ from `linear` by at most 2.3e-5.
- **Deviation?** No.

## Dxx-new · Paired differences

- **Decision.** `paired_differences(results, reference)` takes the per-scorer results from `bootstrap_aucs` (or
  `bootstrap_statistic`) on the same draws and returns, for every other scorer, reference − other: the point
  estimate is the difference of the point estimates, the replicates are the replicate-by-replicate differences, and
  the CI is their percentile CI. It refuses results with different draws (fingerprint), different CI levels or
  different degenerate replicates. Any number of scorers.
- **Why.** Appendix A §8: "CNN − baseline uses the same resamples".
- **Deviation?** No.

## Dxx-new · Generic statistic bootstrap

- **Decision.** `bootstrap_statistic(statistic, draws, ci=...)` bootstraps any statistic on the same draws:
  `statistic(item_weights, cluster_counts)` returns a float, or NaN for a degenerate replicate (dropped and counted).
  `pair_accuracy` exposes per-pair credits and `pr_sweep` takes detection weights, so P1-13 can put sheet CIs on
  pair accuracy and stage 2 with the same machinery.
- **Why.** The stage-2 CI in the spike's claims is a post hoc sheet-level bootstrap (†), and `metrics.json` (PLAN.md
  §4.3) has a sheet CI for `tests.stage2`. Using this is P1-13's choice.
- **Evidence.** [E] On the AUC it reproduces the vectorised path bit for bit. A P@R50 sheet bootstrap of 24,000
  synthetic detections on 20 sheets with 2,000 replicates takes 11.5 s.
- **Deviation?** No; it adds no method.

## Dxx-new · Seed ensemble

- **Decision.** `seed_ensemble(preds)` is the arithmetic mean of the seed probabilities (not of the logits), aligned
  on patch id. Input is seed → DataFrame with `id`, `prob` (the `preds_*.csv` contract). Every seed must hold the
  same set of unique ids with finite probabilities in [0, 1]; otherwise it raises. Output keeps the first seed's row
  order.
- **Why.** Appendix A §7 / Appendix B `"ensemble": "mean of seed probabilities"`. Failing loudly on a missing or
  extra id avoids a silently partial ensemble; a missing seed is the runner's INCOMPLETE case, not ours.
- **Deviation?** No.

## Dxx-new · Same-sheet pair accuracy

- **Decision.** `pair_accuracy(y, score, pair_id, sheet=None)`:
  - Items with `pair_id < 0` (background, −1 in `meta.csv`) are ignored.
  - A pair counts when exactly one positive and one negative carry its id among the items passed. A pair id with a
    single member is dropped and counted (`n_incomplete`, e.g. a stratum-level match split across folds). Two
    positives, two negatives or more than two members raise.
  - With `sheet` given, a pair counts only if both members lie on the same sheet (match levels 1 and 3, the "same
    sheet" levels of Appendix A §5); other pairs are dropped and counted (`n_cross_sheet`). This is the
    same-sheet pair accuracy.
  - **Ties.** Credit 1 if score(positive) > score(negative), **1/2 if equal**, 0 otherwise; accuracy is the mean
    credit, NaN with no pairs. The counts of wins, ties and losses are reported.
- **Why.** The brief's post hoc check ("same-sheet pair accuracy 0.824 (a) and 0.762 (b)") and P1-13's breakdowns.
  Ties count 1/2 so that pair accuracy is the AUC restricted to matched pairs, with the same tie rule. With
  continuous ensemble probabilities, ties are practically absent [I]; they matter for coarse baselines
  (susceptibility class).
- **Alternatives.** Ties as failures (strict) or excluded; restricting to match level 1 only (same sheet and same
  slope bin, as the demo's "Spot the landslide" describes). The level filter is left to the caller: P1-13 can
  pre-filter on `match_level` if it prefers level 1 only.
- **Deviation?** No; Appendix A doesn't define the check.

## Dxx-new · Stage-2 precision–recall sweep

- **Decision.** `pr_sweep(scores, outcomes, n_targets, recall_level, weights=None)` takes each detection's score and
  outcome (`tp`, `fp`, `ignored`, `duplicate`, as in `detections.parquet`) and the number of targets. It is
  independent of geometry; P1-12 does the matching. Input order doesn't matter.
  - **Thresholds.** The operating points are the distinct scores of **all** detections, highest first. The point at
    score t holds every detection with score ≥ t, so tied detections enter together, never one at a time.
  - **TP and FP** accumulate. **Ignored and duplicate detections occupy thresholds but add to neither count**: a
    threshold holding only them is an operating point with the same precision and recall as the previous one.
    So they never change any precision, and the P@R threshold is always a score at which a TP enters.
  - **precision** = TP / (TP + FP), undefined (NaN) while both are 0. **recall** = TP / n_targets (object recall: TP
    are distinct matched targets).
  - **P@R50 (primary)** = precision at the highest threshold with TP ≥ recall_level × n_targets (recall level from
    `cfg["eval"]["thresholds"]["stage2_recall"]` = 0.5; recall exactly 0.5 counts). **Interpolated precision
    (secondary)** = the maximum precision over all operating points with recall ≥ the level. **Max recall** = total
    TP / n_targets.
  - **Not reached.** If no point reaches the level, the result has `status = "not_reached"`, `precision_at_recall`,
    `threshold_at_recall` and `interpolated_precision` are None, and `passes(min_precision)` is False for any
    threshold. Downstream code must treat it as a FAIL (Appendix A §9: "If 50 % recall is never reached, stage 2
    FAILs").
  - A TP count above `n_targets` raises (each target is matched at most once).
- **Why.** Appendix A §9 ("precision at the highest threshold whose recall ≥ 0.50"; "Duplicate (ignored)";
  "precision = TP / (TP + FP)"; "the precision–recall curve sweeps all detections in descending score"). Grouping
  ties is what a threshold means: no threshold can separate two equal scores. The hand-computed test shows that
  breaking the tie at P@R50 with the TP first would give 2/4 instead of the correct 2/5.
- **Alternatives.** Thresholds only at TP/FP detections (gives the same precision values but a different curve
  length); rank-by-rank points within a tie group (depends on an arbitrary order).
- **Notes for P1-12.**
  - The post hoc "ring counted as FP" check is the same sweep after remapping `ignored` → `fp`; duplicates stay
    ignored. TP still takes precedence over the ring, because the matching rule checks TP first.
  - Which scores to pass: we recommend the scores that set the matching order (the NMS scores with the seeded
    1e-9 jitter, if P1-12 keeps them), so the sweep's order equals the matching order. With raw scores, tied
    detections enter together, which is also well defined. P1-12 records its choice.
- **Deviation?** No.

## Notes for downstream tasks

- **P1-13, block-level CI.** The config names only `"unit": "sheet"`. The secondary block CI uses the same `n`,
  `ci` and `seed` with the `block` column as labels (`draw_clusters(meta.block, spec.n_replicates, spec.seed)`).
  P1-16 may want to add a key such as `eval.bootstrap.secondary_unit: "block"` to the frozen config to record this.
- **P1-13, stage-2 bootstrap.** If P@R50 is bootstrapped over sheets, a replicate where 50 % recall is not reached is
  not "degenerate" in the D21 sense; returning NaN would drop it and bias the CI upwards. P1-13 should decide (for
  example, count such replicates separately and report them, or score them 0) and record the choice.
  `paired_differences` refuses results whose NaN replicates differ, so paired stage-2 differences (CNN − baseline)
  need that choice made first.
