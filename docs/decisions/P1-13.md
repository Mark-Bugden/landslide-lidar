# P1-13 decisions: evaluation and verdict

Code: `src/landslide/{evaluate,verdict,figures}.py`, `scripts/evaluate.py`; tests: `tests/test_{evaluate,verdict}.py`
with the synthetic inputs of `tests/eval_synth.py`. Every statistic comes from `landslide.metrics` (P1-05); this task
only decides what is computed on which items and how the results are combined. No real data, run or prediction was
read: everything below was tested on synthetic run directories, baseline files and detections in temporary
directories.

## D25 · Verdict words and precedence

- **Decision.** Each test gets a status. (a) and (b) are PASS, FAIL or INCOMPLETE; stage 2 is PASS, FAIL,
  INCOMPLETE or NOT_RUN. Only a complete test can PASS or FAIL, and the point estimate decides
  (estimate ≥ threshold passes, so equality passes). The verdict (`landslide.verdict.decide`):
  1. any test FAIL → **NOT REPLICATED**, even when other tests are INCOMPLETE or NOT_RUN;
  2. otherwise all three PASS → **REPLICATED**;
  3. otherwise → **INCOMPLETE**.

  So: stage 2 not run because (a) or (b) failed → NOT REPLICATED (rule 1); (a) and (b) pass but stage 2 missing,
  incomplete or not run → INCOMPLETE; stage 2 that never reaches 50 % recall → FAIL → NOT REPLICATED. The words come
  from `replication.verdict_words`; the verdict record lists a reason for every open or failed test.
- **Why.** BRIEF.md "Replication criteria"; Appendix A §1 ("If a completed test is below its threshold, the verdict
  is FAIL even when other runs are missing"; "If 50 % recall is never reached, stage 2 FAILs"); PLAN.md D25.
- **Alternatives.** Treating NOT_RUN as FAIL when (a) and (b) passed (wrong: a run cut by the wall-clock cap is a
  missing run, not a fail); treating INCOMPLETE stage 2 as FAIL (never allowed: INCOMPLETE is never a pass and,
  by the same text, never a completed result).
- **Evidence.** [E] `test_truth_table` covers all 3 × 3 × 4 = 36 combinations against an independent nested
  formulation of the brief's sentences; exactly one combination (PASS, PASS, PASS) is REPLICATED.
  `test_brief_sentences` pins each sentence of the brief.
- **Deviation?** No.

## Dxx-new · Borderline

- **Decision.** A result is borderline when its CI holds both passing and failing values: `ci_low < threshold ≤
  ci_high`. A CI with its lower bound exactly on the threshold is all-pass, so not borderline. Tests (a) and (b)
  report `borderline` (sheet CI, the pre-registered one) and `borderline_block` (secondary); stage 2 reports
  `borderline` on its post hoc sheet CI. Borderline never changes a status or the verdict.
- **Why.** Appendix A §1: "a result whose CI straddles its threshold is called borderline"; the ≥ rule makes the
  threshold itself a passing value.
- **Deviation?** No.

## Dxx-new · Integrity of the runs

- **Decision.** The expected units are every run × seed: `a_f0`…`a_f{n_folds_a−1}`, `b`, `s2` × `train.seeds` (21
  units); in smoke mode `smoke.runs` × `smoke.seeds` with the (a) folds of `smoke.folds`. Each unit directory is
  classified:
  - **done**: exactly one status file, `done.json`, naming this unit, run, seed and mode (`smoke`), with the
    expected config hash, and `history.csv`, `preds_val.csv`, `preds_test.csv` present; `preds_test.csv` has unique
    integer ids, probabilities in [0, 1] and `n_test` rows;
  - **failed** (`failed.json`), **interrupted** (`interrupted.json`), **missing** (no status file; a stray
    `history.csv` is noted);
  - **hash_mismatch**: a `done.json` that is otherwise valid but carries another config hash;
  - **invalid**: anything else (two status files, unreadable JSON, missing or inconsistent outputs).

  Only a done unit counts. The expected hash is `configs/landslide.sha256` once it exists (after the freeze) and the
  current config's `config_hash` before. If the sha256 file exists and the config on disk hashes differently, the
  evaluation refuses to run (`ConfigMismatchError`): a verdict computed with other thresholds is not the
  pre-registered test. `integrity` in `metrics.json` lists every unit's status and problems, plus its
  `done.json` fields (best epoch, inner-val AUC, epochs, stop reason, sizes, seconds, peak GPU memory, commit,
  dirty flag).
- **Why.** The card ("check every `done.json` … list missing / failed / interrupted units"); BRIEF.md phase 3 ("If
  any run failed, is missing or has a config-hash mismatch, report that first"); P1-06's run-directory contract.
- **Alternatives.** Accepting a hash-mismatched unit with a warning (rejected: it was not trained under the frozen
  config, so the test would not be the pre-registered one); continuing with a warning on a changed config (rejected:
  the thresholds come from the config).
- **Evidence.** [E] `test_missing_unit_is_incomplete`, `test_failed_and_interrupted_units`,
  `test_hash_mismatch_unit`, `test_config_differs_from_frozen_hash`, `test_invalid_units` (wrong `n_test`, two
  status files, no predictions, smoke flag, a probability of 1.5).
- **Deviation?** No.

## Dxx-new · When a test is complete

- **Decision.** Test (a) is complete when every `a_f*` unit is done, each fold's seeds predict the same id set (the
  seed ensemble refuses otherwise), every predicted id is in `meta.csv` and in that fold's test set (fold k,
  not background), no patch is predicted by two folds, and the pooled ids equal the (a) test set of `meta.csv`
  (all non-background rows with fold ≥ 0). Test (b) likewise with `group_b == "test"`. In smoke mode the pooled ids
  must be a non-empty subset (the smoke subset). A test whose test set lacks a class has no AUC and is
  INCOMPLETE. Anything else makes the test INCOMPLETE, with the reason in `problems`.
- **Why.** "A test with any missing run is INCOMPLETE"; a model that predicted only part of the test set has not run
  the pre-registered test.
- **What is still reported for an incomplete test.** `per_unit` AUCs of the done units, `per_fold` for folds whose
  seeds are all done, `per_seed` for seeds done on every fold, the baselines and the slope-only check on the full
  `meta.csv` test set. `estimate`, `pass`, CIs and breakdowns stay null: a partial number is never the test's result.
- **Evidence.** [E] `test_predictions_must_cover_the_test_set`, `test_seed_disagreement_is_incomplete`,
  `test_missing_unit_is_incomplete`.
- **Deviation?** No.

## Dxx-new · Seed ensemble and pooled out-of-fold predictions

- **Decision.** Per run, `metrics.seed_ensemble` (mean of the seed probabilities, aligned on id) of the units'
  `preds_test.csv`; for (a) the five fold ensembles are concatenated (pooled out-of-fold) and the AUC is computed once
  over all of them. Per fold = the AUC of that fold's ensemble on its own patches; per seed = the AUC of one seed's
  predictions pooled over the folds; per unit = each unit's own AUC.
- **Why.** Appendix A §7 ("The run prediction is the mean of the seed probabilities") and §8 ("ROC AUC of the pooled
  out-of-fold ensemble predictions"); "per-fold and per-seed AUC" (§8 secondary).
- **Evidence.** [E] `test_pooled_oof_ensemble_matches_independent_computation`: estimate, per fold and per seed equal
  `sklearn.roc_auc_score` on an independently computed ensemble; `test_ensemble_does_not_depend_on_row_order`
  (shuffled rows → byte-identical `metrics.json`).
- **Deviation?** No.

## Dxx-new · Confidence intervals and paired differences

- **Decision.** The items of a test are its patches sorted by id. Two sets of draws are made once per test with
  `eval.bootstrap` (n 2,000, seed 123, percentile 95 %): over sheets (primary, pre-registered) and over blocks
  (secondary, P1-05's note). The CNN and every baseline are bootstrapped on the **same** draws, so `paired_diffs` are
  CNN − baseline replicate by replicate (`metrics.paired_differences`) for both units. Breakdowns (by kraj, flysch,
  source, Jihomoravský non-flysch) draw their own sheet resamples of the subset with the same seed (a subset has
  other sheets). The same-sheet pair accuracy is bootstrapped on the test's sheet draws (each pair belongs to its
  sheet). Degenerate replicates follow D21 (dropped and counted).
- **Why.** Appendix A §8 ("Paired differences. CNN − baseline uses the same resamples"; "Block-level bootstrap CI"
  secondary).
- **Evidence.** [E] `test_cis_and_paired_differences_share_draws` recomputes the draws, the replicate AUCs, the CIs
  and the paired CIs independently.
- **Deviation?** No.

## Dxx-new · Stage-1 baselines

- **Decision.** `data/baselines/preds_{a,b}.csv` (P1-11): every column except `id` and `fold` is a scorer (higher =
  more landslide-like). They are aligned on the test's ids. Full mode requires the baseline ids to equal the test
  ids exactly; smoke mode allows extra ids (the smoke CNN predicts a subset). For (a), the file's `fold` must agree
  with `meta.csv`. A missing, unreadable or mismatched file is reported with its status and gives no paired
  differences; it never changes the verdict. Kinds follow Appendix A §10 (`slope_only`, `susceptibility`: non-ML
  baselines; `slope_susc_lr`, `terrain_stats_lr`: classical-ML comparators; `terrain_stats_gbm`: secondary).
  Per-fold baseline AUCs are reported for (a).
- **Evidence.** [E] `test_missing_baselines_do_not_change_the_verdict`, `test_baseline_id_mismatch`.
- **Deviation?** No.

## Dxx-new · Breakdowns and secondary checks

- **Decision.**
  - **Per negative source** (both tests): all test positives against the negatives of one source (random, quarry,
    spoil, rock, cut), with a sheet CI. "Positives against each negative source" (Appendix A §8) does not say which
    positives; all of them keeps each comparison on the same positives.
  - **(b) by kraj, by flysch flag and by kraj × flysch** (keys `"<kraj> | flysch"` / `"<kraj> | non-flysch"`), each
    with a sheet CI. The spike's "non-flysch Jihomoravský AUC" is `secondary.jihomoravsky_nonflysch` (same numbers
    as `by_kraj_flysch["Jihomoravský | non-flysch"]`).
  - **Slope-only check**: the AUC of `meta.csv`'s `slope_mean` (the patch-mean slope, i.e. the unfitted
    `slope_only` score) on each test set with a sheet CI; about 0.5 expected. It does not depend on P1-11's file.
- **Why.** Appendix A §8 secondary list; BRIEF.md post hoc checks.
- **Evidence.** [E] `test_breakdowns`.
- **Deviation?** No.

## Dxx-new · Same-sheet pair accuracy: scope

- **Decision.** The headline (`secondary.pair_accuracy.<test>.same_sheet`) counts the matched pairs whose two
  members lie on the same sheet (`metrics.pair_accuracy` with `sheet`), i.e. match levels 1 (same sheet, exact
  bin) and 3 (same sheet, adjacent bin): with P1-09's level-by-level matching a positive that reaches level 2, 4,
  5 or 6 had no same-sheet candidate, so its negative lies on another sheet. The counts per match level are
  reported (`by_match_level`) so this is visible. A sheet CI is attached. Also reported, not as the headline:
  level 1 only (same sheet and same 2° bin, the demo's "Spot the landslide" pair) and all pairs.
- **Why.** The brief's check is named "same-sheet pair accuracy"; P1-05's `pair_accuracy` defines it by the sheet.
  Restricting further to level 1 would be a different quantity from the name; the level-1 number is still there
  if the demo wants it.
- **Alternatives.** Level 1 only; all pairs (cross-sheet pairs compare patches from different terrain).
- **Evidence.** [E] `test_pair_accuracy_scope_is_same_sheet` (synthetic world with level-1, -2 and -3 pairs).
- **Deviation?** No; the check is post hoc and Appendix A does not define it.

## Dxx-new · Stage 2: inputs, targets and the evaluated sheets

- **Decision.**
  - Detections come from `<stage2>/detections.parquet` (P1-12's contract). The CNN is scorer `"cnn"`; every other
    scorer is a comparator. The `score` column is passed to `metrics.pr_sweep` as given (P1-05 recommends that it
    carry the NMS jitter so the sweep's order equals the matching order; that is P1-12's choice).
  - **Targets** are read from `data/derived/polygons.parquet`: `eligible` polygons whose `sheet` (the assigned
    sheet) is an evaluated sheet. `run_evaluation(..., targets=...)` accepts them as an argument instead (used by the
    tests). `sheets.parquet` is not needed: the sheet list and strata come from `replication.splits.stage2_sheets`.
  - **Evaluated sheets**: the 20 reserved sheets in full mode; in smoke mode the sheets of the CNN detections, which
    must be reserved sheets and number `smoke.stage2_sheets`. Every scorer must have detections on every evaluated
    sheet and none elsewhere.
  - **A TP counts on its target's sheet.** For the per-stratum results and the sheet bootstrap, a TP is attributed to
    the sheet its target is assigned to (via `target_objectid`), every other detection to the sheet it lies on. A
    detection near a sheet edge can match a target assigned to the neighbouring reserved sheet; attributing it to its
    own sheet could give a resample more TPs than targets.
  - Malformed CNN detections (unknown outcome, a TP without a known target, a target matched twice, a sheet missing)
    make stage 2 INCOMPLETE with the reason, never a crash and never a FAIL.
- **Evidence.** [E] `test_stage2_metrics` (values equal `pr_sweep` on the raw detections), `test_tp_counts_on_its_target_sheet`,
  `test_stage2_missing_sheet_is_incomplete`, `test_stage2_bad_detections_are_incomplete_not_a_crash`,
  `test_stage2_targets_can_be_passed_in`.
- **Deviation?** No.

## Dxx-new · Stage 2: status

- **Decision.** NOT_RUN when no `s2` unit has any status file and there is no CNN detection. INCOMPLETE when an `s2`
  unit is not done, the CNN detections are missing or unusable, the targets cannot be built or there are none.
  Otherwise the test is complete: P@R50 = `pr_sweep(...).precision_at_recall` over the pooled detections of all
  evaluated sheets; not reached → FAIL (`reached: false`, `estimate: null`); else PASS if ≥ 0.30. Also reported:
  interpolated precision, max recall, the score threshold, counts, `by_stratum` (flysch / non-flysch: that stratum's
  detections and targets) and, in `secondary.stage2_ring_as_fp`, the same sweep with `ignored` remapped to `fp`
  (duplicates stay ignored; P1-05's note). There is no per-fold or per-seed stage-2 result (the detections are of
  the seed ensemble), so those fields are null.
- **Why.** Appendix A §9 metric and comparisons; the runner trains `s2` only if (a) and (b) pass.
- **Evidence.** [E] `test_stage2_not_reached_is_a_fail`, `test_stage2_low_precision_is_a_fail`,
  `test_stage2_not_run`, `test_stage2_units_without_detections_is_incomplete`, `test_stage2_missing_unit_is_incomplete`.
- **Deviation?** No.

## Dxx-new · Stage 2: post hoc sheet bootstrap and the not-reached rule

- **Decision.** The CI of P@R50 (`tests.stage2.sheet_ci`, flagged `post_hoc: true`) resamples the evaluated sheets
  with replacement (`eval.bootstrap` n, seed, percentile). In replicate b each sheet drawn c times contributes its
  detections and its targets c times (detection weights and a weighted target count in `pr_sweep`). **A replicate
  whose pooled detections never reach 50 % recall counts as precision 0** (a fail at that replicate) and is kept;
  `n_not_reached` reports how many. Only a replicate with no target at all would be degenerate (NaN, dropped and
  counted, D21); with ≥ 5 targets on every reserved sheet that cannot happen. The CI is secondary and never decides.
  The same draws serve the stage-2 comparators, so CNN − comparator paired differences are reported too (post hoc).
- **Why.** Such a replicate is a real outcome of resampling (the method says not reaching 50 % recall is a FAIL), not
  a replicate without a defined statistic as in D21. Dropping it would keep only the resamples that happen to reach
  the recall level, which biases the CI upwards; it would also give the CNN and a comparator different dropped
  replicates and break the pairing (`paired_differences` refuses that). Precision 0 is the value that is a fail
  under any threshold, as the primary rule treats it.
- **Alternatives.** Dropping and counting (biased upwards); using the max recall's precision (not the defined
  metric); a separate "not reached" share without a CI (loses the interval).
- **Evidence.** [E] `test_stage2_bootstrap_counts_not_reached_as_zero`: a synthetic case whose point estimate
  reaches 50 % recall while some resamples do not; the CI and `n_not_reached` equal an explicit resample-by-resample
  computation, and dropping those replicates would raise the lower bound.
- **Deviation?** No; the bootstrap is post hoc (the spike's † claim).

## Dxx-new · Spike claims and discrepancies

- **Decision.** The spike's numbers are a constant in `landslide.evaluate` (`SPIKE_CLAIMS`), each with the exact
  text from BRIEF.md (a test checks the text is in the brief) and the `metrics.json` path of our number. A
  discrepancy is our point estimate **outside** the spike's 95 % CI (bounds inside). Claims without a CI (stage-2
  comparators, pair accuracy, ring as FP, Jihomoravský non-flysch) are compared but cannot be flagged
  (`outside_spike_ci: null`, with a note). Discrepancies never change the verdict. Our baselines are compared under
  the spike's best non-CNN name for each test (`terrain_stats_lr` for (a), `terrain_stats_gbm` for (b),
  `slope_susc_lr` and `random` for stage 2).
- **Why.** BRIEF.md "Replication criteria" ("If one of your point estimates falls outside the spike's 95 % CI, report
  it as a discrepancy … does not change the verdict").
- **Evidence.** [E] `test_spike_claims_are_the_briefs`, `test_discrepancy_flag_boundaries`.
- **Deviation?** No.

## Dxx-new · `results/metrics.json` schema (version 1)

All keys are sorted in the file. CI objects are `{unit, low, high, level, n_replicates, n_used, n_degenerate}`
(stage 2 adds `post_hoc`, `not_reached_rule`, `n_not_reached`); `n` objects are `{patches, positives, negatives,
sheets, blocks}` (stage 2: `{sheets, targets, detections, tp, fp, ignored, duplicate}`).

- `schema_version` (1), `smoke` (bool), `config_hash` (the expected hash), `git_commit` (the training commit: the
  single `git_commit` of the done units, null if they differ, see `integrity.git_commits`), `verdict`
  (REPLICATED / NOT REPLICATED / INCOMPLETE), `verdict_detail` (`a`, `b`, `stage2` statuses, `reasons`, `rule`).
- `integrity`: `config_hash_expected`, `config_hash_source` (frozen | current_config), `config_hash_current`,
  `n_expected`, `n_done`, `missing`, `failed`, `interrupted`, `hash_mismatch`, `invalid` (unit name lists),
  `git_commits`, `git_dirty_units`, `ok`, `units` (per unit: status, problems and the `done.json` fields, the error
  of a failed unit, the epochs of an interrupted one).
- `tests.a`, `tests.b`: `test`, `definition`, `metric` ("roc_auc"), `status`, `complete`, `problems`, `units`,
  `missing_units` (name → status), `estimate`, `threshold`, `pass`, `borderline`, `borderline_block`, `sheet_ci`,
  `block_ci`, `n`, `per_fold` ((a) only: fold → {run, complete, auc, n_patches}), `per_seed` (seed → {complete,
  auc, n_patches}), `per_unit` (unit → {auc, n_patches}), `breakdowns` (`by_source`; (b) also `by_kraj`,
  `by_flysch`, `by_kraj_flysch`; each entry {auc, sheet_ci, n}).
- `tests.stage2`: `test`, `definition`, `metric` ("precision_at_recall"), `recall_level`, `status` (also NOT_RUN),
  `complete`, `problems`, `units`, `missing_units`, `sheets`, `estimate` (P@R50, null if not reached), `reached`,
  `threshold`, `pass`, `borderline`, `interpolated_precision`, `max_recall`, `score_threshold`, `sheet_ci` (post
  hoc), `block_ci` (null), `n`, `per_fold` (null), `per_seed` (null), `breakdowns.by_stratum` (flysch / nonflysch).
- `baselines.a`, `baselines.b`: the file's `status` (ok | missing | unreadable | invalid | id_mismatch |
  fold_mismatch), `file`, id counts, and `scorers` (name → {kind, auc, sheet_ci, block_ci, per_fold for (a)}).
  `baselines.stage2`: `status`, `file`, `scorers` (name → {kind, status, estimate, reached, interpolated_precision,
  max_recall, score_threshold, recall_level, n, sheet_ci, by_stratum, ring_as_fp}, or {kind, status: error,
  problem}).
- `paired_diffs`: `definition`; `a` and `b` → `sheet` / `block` → baseline → {estimate, ci}; `stage2` → `sheet` →
  comparator → {estimate, ci, post_hoc}.
- `secondary`: `slope_only_check` (a, b → {score, auc, sheet_ci, expected, n}), `pair_accuracy` (a, b →
  {primary: "same_sheet", same_sheet {accuracy, n_pairs, n_correct, n_ties, n_wrong, n_cross_sheet, n_incomplete,
  by_match_level, sheet_ci}, level_1 {…}, all_pairs {…}}), `jihomoravsky_nonflysch` ({auc, sheet_ci, n}),
  `stage2_ring_as_fp` (a stage-2 sweep record).
- `bootstrap`: n, ci, seed, method, primary_unit ("sheet"), secondary_unit ("block").
- `spike_claims`: id → {claim, value, ci, ci_note?, ours (dotted path)}.
- `discrepancies`: `rule`, `flagged` (claim ids), `comparisons` (one per claim: id, claim, spike, spike_ci, ours,
  ours_path, outside_spike_ci, note).
- `figures.learning_curves`: {file, runs drawn} or null.

`results/metrics_table.md` is rendered from the same (rounded) dictionary: the verdict and its reasons, the unit
summary, the three tests next to the spike's claims with discrepancy flags, the baselines with CNN − baseline, the
post hoc checks, and the per-fold / per-seed spread.

- **Why.** PLAN.md §4.3 fixes the top level and asks P1-13 to fix the rest; `metrics.json` is the single source for
  REPLICATION.md and the model card.
- **Evidence.** [E] `test_schema`.
- **Deviation?** No.

## Dxx-new · Re-runnable, byte-identical outputs

- **Decision.** `scripts/evaluate.py` reads only saved outputs. `metrics.json` is written with sorted keys, 2-space
  indent, UTF-8, LF and a trailing newline; floats are rounded to 6 decimals (NaN/inf → null, −0.0 → 0.0). Pass,
  fail and discrepancy flags are decided on the unrounded values, before rounding. There is no timestamp in any
  output, and `git_commit` is the training commit from `done.json`, not the commit at evaluation time, so phase 3's
  re-run gives the same file. The figure is drawn on matplotlib's Agg canvas without the "Software" PNG metadata.
  Files are written atomically. When there is no history to draw, an old figure is deleted rather than left stale.
- **Why.** The card; PLAN.md P3-01 ("`metrics.json` must come out identical").
- **Evidence.** [E] `test_byte_identical_reruns` (`metrics.json`, `metrics_table.md`, `learning_curves.png`
  identical after deleting and re-running).
- **Deviation?** No.

## Dxx-new · Learning curves

- **Decision.** `figures/learning_curves.png`: one row per run with any history (a_f0…a_f4, b, s2), a BCE panel
  (`train_loss`, `val_loss`) and an ROC AUC panel (`train_auc`, `val_auc`). Each seed's train curve is faint blue
  and its validation curve faint orange; the bold curves are the seeds' mean over the epochs every seed has run; a
  dot marks each done unit's `best_epoch` on its validation curves. Histories of failed or interrupted units are
  drawn without a dot. No map, sheet or geometry is drawn.
- **Why.** Appendix A §7 "Monitoring".
- **Evidence.** [E] rendered on the synthetic world and inspected; `test_learning_curve_figure`.
- **Deviation?** No.

## Dxx-new · Smoke mode

- **Decision.** `scripts/evaluate.py --smoke` uses `Paths(smoke=True)`: run directories, stage-2 detections,
  `results/`, `figures/` and the log all under `data/smoke/`. Inputs (`meta.csv`, baselines, `polygons.parquet`) are
  read from their usual place (`Paths` never redirects inputs), and are only read. The expected units are the
  config's `smoke` block; a `done.json` whose `smoke` flag differs from the mode is invalid. `metrics_table.md` carries a SMOKE TEST banner.
- **Why.** PLAN.md P1-13 ("in smoke mode, read and write only `data/smoke/`"), P1-14 item 7, D24.
- **Evidence.** [E] `test_smoke_reads_and_writes_only_smoke_locations` runs the script with the real config and a
  temporary `LANDSLIDE_DATA_DIR`: every new file is under `data/smoke/`, the tracked `results/`, `figures/` and
  `logs/` are untouched, and a decoy full-mode run directory is not read.
- **Deviation?** No.
