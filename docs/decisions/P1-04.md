# P1-04 decisions: terrain channels library

Modules: `src/landslide/dtm.py` (raster access, invalid rule, pixel-corner transforms), `src/landslide/channels.py`
(the seven channels), `src/landslide/sat.py` (summed-area tables). Tests: `tests/test_{dtm,sat,channels}.py`
(synthetic), `tests/test_channels_real.py` (real DTM, gated on G1), `tests/test_channels_benchmark.py` (opt-in).

## D18 · Channel numerics

- **Decision.** All channels in float64, stacked in `cfg["channels"]` order. Grid step g = `dtm.cell_m` = 2 m. Arrays
  are (row, col); x runs along columns and y along rows (downwards). Every formula below is invariant under that
  choice of axes (reflecting y flips the signs of q and s together).
  - **slope** (radius 1): on the raw z, p = (z[i, j+1] − z[i, j−1]) / 2g, q = (z[i+1, j] − z[i−1, j]) / 2g,
    slope = degrees(arctan(√(p² + q²))).
  - **lrm_s, lrm_l** (radius 5 and 25): z − `scipy.ndimage.uniform_filter(z, size)` with size 11 and 51 px (centred,
    `mode="nearest"`).
  - **curv_prof, curv_plan** (radius 4 + 1): z is smoothed with a Gaussian, σ = 1 px, truncate 4 (scipy radius
    int(4σ + 0.5) = 4 px, `mode="nearest"`). The derivatives are the Zevenbergen–Thorne central differences of the
    smoothed grid zs (3 × 3 stencil), with c = zs[i, j] and e, w, s, n the neighbours at column ±1 and row ±1:
    p = (e − w)/2g, q = (s − n)/2g, r = ((e + w) − 2c)/g², t = ((s + n) − 2c)/g²,
    s = ((zs[i+1, j+1] + zs[i−1, j−1]) − (zs[i+1, j−1] + zs[i−1, j+1]))/4g². Then
    k_prof = −(p²r + 2pqs + q²t) / ((p² + q²)(1 + p² + q²)^1.5),
    k_plan = −(q²r − 2pqs + p²t) / ((p² + q²)(1 + p² + q²)^0.5),
    k = 0 where p² + q² < ε = 1e-12, and the channel is asinh(k / k0) with k0 = 0.001 m⁻¹. With this sign
    convention a bowl (concave) is negative and a dome (convex) positive.
  - **svf** (radius 20): 16 directions θ_k = k · 22.5°, k = 0..15, unit vector (cos θ, sin θ) along (columns, rows);
    radii r = 1..20 px. The DTM is sampled at (i + r sin θ, j + r cos θ) by bilinear interpolation (a single tap
    when an offset is an integer). Horizon tangent t_k = max_r (z_r − z0) / (r g), observer on the ground (no
    height offset). SVF = 1 − (1/16) Σ_k sin(max(0, atan t_k)), evaluated as max(0, t_k) / √(1 + max(0, t_k)²).
  - **detr** (per window): z − (mean + a·u + b·v), where u and v are the column and row coordinates centred on the
    window. On a full rectangular grid u, v and the constant are orthogonal, so the least-squares plane is exact in
    closed form: a = Σ u (z − mean) / Σ u², b likewise. It is fitted over the 150 × 150 patch (`patch_channels`),
    the whole block (`compute_channels`) or any stack of windows (`detrend`, for stage 2).
- **Why.** Appendix A §6 and the D18 defaults; Appendix B `channel_params` for every value it has.
- **Alternatives.**
  - Evans–Young 3 × 3 least-squares derivatives instead of Zevenbergen–Thorne. Not chosen: ZT is the
    central-difference scheme, consistent with "central differences" for slope and with the PLAN's "Gaussian 4 px +
    1" margin budget.
  - `np.gradient` (one-sided at the edges). Not needed, because edge pixels are masked anyway (D18a-new).
  - An observer height for SVF. Not chosen: Appendix A doesn't mention one; the plain Zakšek-style form is used.
- **Evidence.** [E] `tests/test_channels.py`:
  - plane z = 420 + gx·x + gy·y for five gradients: slope = atan(|∇z|), LRM 0, curvatures 0, detr 0 and the
    closed-form SVF, all to 1e-9;
  - paraboloids (bowl, dome, saddle): both curvatures equal their closed forms to 1e-9 with the expected signs;
    the apex gives 0 by the flat rule; SVF < 1 inside the bowl and exactly 1 at the dome apex;
  - an independent SVF (scipy `map_coordinates` order 1, `arctan`, `sin`) agrees to 1e-9 at 40 random pixels;
  - `detrend` equals `numpy.linalg.lstsq` to 1e-9.
- **Deviation?** No.

## D18a-new · Validity, NaN propagation and boundary handling

- **Decision.** A per-pixel channel c is finite at (i, j) iff every pixel within Chebyshev radius R_c of (i, j) lies
  inside the array and is valid. The implementation fills invalid cells with 0, computes, then sets NaN wherever a
  summed-area table of the invalid mask counts ≥ 1 invalid cell in the (2R_c + 1)² square. Squares that leave the
  array count as invalid, so the filters' boundary modes never reach a finite output. detr is NaN over the whole
  window if any of its pixels is invalid. `patch_channels` treats cells outside the raster as invalid.
- **Why.** Appendix A §5 uses only patches whose patch plus 28 px context is NaN-free, so the rule only has to be
  strict, deterministic and identical for patches and full rasters. The square footprint is D4-symmetric, simple to
  state, and conservative for SVF (which reads rays, not the full square).
- **Alternatives.**
  - Letting NaN propagate through the arithmetic. Rejected: `uniform_filter`'s running sum keeps a NaN for the rest
    of the line. [E] One NaN in a 200 × 200 block gave 24,025 NaN outputs instead of 121.
  - Exact ray footprints for SVF. More complex, and no different on the fully valid patches the dataset uses.
- **Evidence.** [E] `test_nan_propagation_single_cell`: the NaN set equals the radius-R square around the invalid
  cell exactly (plus the edge band), and values outside it don't change (≤ 1e-9) when the cell's value changes.
  `test_nan_and_raster_edge_in_patch_context`: a NaN 20 px into the context hits only the kernels with R ≥ 20, and
  only in the first R − 19 patch rows. A context that leaves the raster by 18 px hits only the kernels with R > 10.

## D18b-new · Margin budget (28 px)

- **Decision.** Footprint radii: slope 1, lrm_s 5, lrm_l 25, curv_prof and curv_plan 4 + 1 = 5, svf 20. The worst
  case is 25 ≤ 28. `channel_params(cfg)` computes the radii from the config and raises `ValueError` if any exceeds
  the context. It is an explicit check rather than an `assert` statement, which `python -O` would strip. Every
  public channel function goes through it.
- **SVF radius.** PLAN.md says "SVF 20 px + 1 for interpolation". Our SVF footprint is exactly 20, because an
  integer offset is sampled with one tap (the axis directions at r = 20 read pixel 20 only); every other tap pair
  lies within 20. The radius is derived from the sampling plan in code, not typed in.
- **Evidence.** [E] `test_margin_budget`; `test_margin_violation_raises` (svf_radius_px 29, lrm_large_px 59,
  curv_sigma_px 7 and context 24 all raise).

## D18c-new · One code path for patches and full rasters

- **Decision.** One kernel, `_terrain(block, margin)`, computes channels 0–5 on a block and returns its interior.
  - `patch_channels(z, r, c, cfg)`: block = patch ± 28 px (NaN outside the raster), then crop to 150 × 150. detr is
    taken from the 150 × 150 z crop.
  - `full_channels(z, cfg)`: tiles of 256 px, each with a 28 px halo, through the same kernel, stitched. Returns
    channels 0–5 (or a named subset, e.g. `names=["slope"]` for P1-09). Stage 2 removes the plane per window with
    `detrend` or its GPU equivalent.
  - `compute_channels(z_block, cfg)`: the kernel with margin 0 plus detr over the whole block.
  - `terrain_channels(z, cfg)`: the kernel on a whole array at once (no tiles). Used as the reference "full-raster
    computation" in tests.
- **Why.** The P1-04 card: "Patches and stage 2 use one code path." Tiling also bounds memory and keeps the working
  arrays in cache (about 7× faster per element than sheet-sized arrays [E]).
- **Evidence.** [E]
  - Slope, curvatures and SVF are bitwise identical between patches, tiles and the direct computation, because each
    output pixel is computed from the same inputs in the same order.
  - LRM differs only through `uniform_filter`'s running sum: tiled vs direct ≤ 1.7e-12 on the 520 × 470 test raster
    (tile 96, 3 threads).
  - 30 patches, including some touching the raster edge, the invalid corner and holes: identical NaN masks and
    ≤ 5e-9.
  - On the full-size synthetic 2,850 × 2,400 raster, max |patch − full| = 1.7e-12 over 30 patches and max
    |direct − tiled| = 5.1e-12, against the 5e-9 bound of Appendix A §6.
  - Tile size and thread count don't change the result (bitwise for the same tiles).

## D18d-new · Exact D4 equivariance

- **Decision.**
  - The 16 SVF unit vectors are built to be exactly closed under the 8 grid symmetries. The first quadrant is
    computed once, mirrored about the diagonal, with (√½, √½) at 45° (`cos` and `sin` of π/4 can differ by one ulp
    between math libraries), and turned by exact 90° swaps.
  - The separable Gaussian is applied in both axis orders and the results averaged, so smoothing commutes exactly
    with transposition. scipy's symmetric 1-D correlation is already bitwise flip-symmetric [E].
  - The finite-difference and curvature expressions are ordered so that each transform only permutes commutative
    sums or flips signs. For example r uses (e + w) − 2c, not e − 2c + w, and 2·(p·q)·s.
- **Why.** Appendix A §6: augmentation and TTA rely on channels(T z) = T channels(z). The card requires this to
  1e-9.
- **Evidence.** [E] Max error over the 8 transforms on a 200 × 200 synthetic block with holes and an invalid corner:
  - slope and both curvatures 0 (bitwise);
  - SVF 1.5e-14;
  - LRM 1.5e-12;
  - detr 1.4e-13 (clean 150 × 150 window).

  NaN masks are identical. The patch-level test maps corners through the transform (the corner lattice is
  (n+1) × (n+1)) and passes for all 8 transforms.

## D18e-new · Method values that have no Appendix B key (config keys requested)

- **Decision.** Four values come from Appendix A's prose or from D18, not from Appendix B:

  | key | value | source |
  | --- | --- | --- |
  | `context_px` | 28 | Appendix A §5 "the patch plus its 28 px channel context"; §6 "a 28 px margin" |
  | `curv_truncate` | 4.0 | D18 "Gaussian σ = 1, truncate 4" |
  | `curv_flat_eps` | 1e-12 | D18 "0 where p² + q² < ε"; the value is ours (below) |
  | `svf_r_min_px` | 1 | D18 "r = 1…20 px" |

  `channel_params` reads them from `cfg["replication"]["channels"]` if that block exists, and otherwise from
  `channels.METHOD_DEFAULTS`, which holds exactly these values. **Request to P1-02 / P1-16:** add
  `"channels": {"context_px": 28, "curv_truncate": 4.0, "curv_flat_eps": 1e-12, "svf_r_min_px": 1}` to the config's
  `replication` block, so the frozen config and its hash carry them. No code change is needed after that.
- **ε = 1e-12** means |∇z| < 1e-6 m/m. It is far above float64 noise in the smoothed gradient (~3e-14 for z ≈ 500 m),
  so a genuine gradient is never zeroed by rounding, and exactly flat cells (lakes: constant z gives p = q = 0
  exactly) get 0. In near-flat cells the curvature is bounded by the Hessian's eigenvalues anyway, so ε only guards
  the division.
- **Alternatives.** Putting the keys in `channel_params`: P1-02's card keeps Appendix B keys verbatim and puts our
  own choices in `replication`. Hard-coding them: against PLAN.md §3 rule 6.
- **Deviation?** No; these are readings of Appendix A and D18.

## D18f-new · Invalid rule and raster access

- **Decision.**
  - `dtm.invalid_bounds(cfg)` parses `cfg["dtm"]["invalid_rule"]` strictly. It must contain exactly one `z <= a`
    and one `z > b`, giving (0, 2000); anything else raises.
  - Invalid cells become NaN: non-finite, the raster's nodata value, z ≤ 0 (so exactly 0 m, the out-of-border fill,
    is invalid) or z > 2000.
  - `read_dtm` opens with `rasterio.open(path, mode="r")`, reads band 1 masked and returns float64. A window may
    extend past the raster (NaN fill) and comes with its own transform. Channel functions take arrays that already
    follow the rule; they treat any non-finite cell as invalid.
- **Why.** Appendix B `dtm.invalid_rule`; brief note 1 (0 m outside the border; the package already has NaN for
  NoData and for values outside [−100, 2000] m).
- **Alternatives.** Numeric config keys for the two thresholds. That would duplicate the rule string; P1-02 can add
  them at the freeze if preferred.
- **Evidence.** [E] `tests/test_dtm.py` on a synthetic GeoTIFF with 0 m cells, NaN, 2500 m and a nodata value: 8
  invalid cells found, the file's sha256 unchanged after reading, and window and boundless reads checked.

## D11 · Pixel-corner convention (as implemented in `landslide.dtm`)

- **Decision.**
  - Corner (r, c) is the top-left corner of pixel (r, c), at world `transform * (c, r)` (`corner_xy`).
  - A patch of px = 150 centred on corner (r, c) covers pixel rows r − 75 … r + 74 (`patch_slices`: slice
    r − 75 : r + 75; with the margin, r − 103 : r + 103), and the same for columns.
  - `patch_bounds` gives its 300 m square. `xy_corner` returns the nearest corner and raises beyond 1e-6 px.
    `xy_pixel` floors to the containing pixel. `pixel_center_xy` is corner (r + ½, c + ½).
- **Why.** PLAN.md D11 (owner P1-09); these are the transforms P1-09, P1-10 and P1-12 use.
- **Evidence.** [E] Round trips over 100 random corners. Corners keep the native alignment (x ≡ 0.4, y ≡ −0.12 mod
  2 m) on a grid built like the brief's recipe. Patch bounds are 300 m × 300 m, centred on the corner.

## D18g-new · Summed-area tables

- **Decision.**
  - `integral(a)` has shape (H + 1, W + 1).
  - Corner-centred boxes of half-size h use table rows r − h and r + h: h = 75 for the patch and h = 103 for the
    patch plus its context (P1-09's validity screen: count == 206²). Pixel-centred boxes of radius R are used for
    the channel masks.
  - `ValueSat` keeps exact integer validity counts (int32 below 2³¹ cells) and float64 sums of (value − mean of the
    valid values), for precision.
  - `mean(..., require_all_valid=True)` is the default: NaN unless the whole box is valid, as the pipeline needs.
    `False` gives the mean of the valid cells.
  - Point queries outside the array raise; numpy's negative indices never wrap round. Dense grids put −1 (counts) or
    NaN (means) where the box doesn't fit.
- **Evidence.** [E] `tests/test_sat.py`:
  - every function against brute-force loops, with NaN;
  - patch means of a 1,500 × 1,400 field around 1,000 m to 1e-10.

## Benchmark

- **Setup.** Synthetic 2,850 × 2,400 float64 raster (`tests/terrain_synth.py`, seed 2026). i5-11600K (6 cores, 12
  threads, 12 MB L3), Python 3.13.15, numpy 2.5.5, scipy 1.18.1. To reproduce:
  `$env:LANDSLIDE_BENCH = "1"; uv run pytest tests/test_channels_benchmark.py -s`.
- **Full raster** (`full_channels`, channels 0–5) [E]:

  | Threads | Time per sheet |
  | --- | --- |
  | 1 | 8.5–9.1 s |
  | 2 | 4.8 s |
  | 3 (the default, `DEFAULT_WORKERS`) | 3.9–5.4 s |
  | 4 | 3.9 s |
  | 6 | 6.7 s |

  Above 4 threads, L3 contention slows it down. Single-threaded, the time splits into SVF 6.7 s, curvatures 1.3 s,
  slope 0.35 s and each LRM 0.23 s.
- **Memory.** Traced peak 373 MB, of which 328 MB is the output (6 × 55 MB). For comparison, the direct
  whole-array `terrain_channels` (no tiles) takes 24 s with a 1.4 GB traced peak on the same raster; it is only a
  test reference.
- **Single patch** (`patch_channels`, 7 channels, one thread) [E]: median 29 ms, max 39–45 ms over 30 patches.
- **Implications** [I]: P1-10's roughly 11,200 patches take about 5–6 min; stage 2 takes about 20 × 5 s. SVF is
  vectorised per (direction, radius) sample over whole tiles, using preallocated buffers.
- **Caveat.** Timings vary by about ±30 % with other load on the machine, because parallel agents were running.

## D18h-new · SVF on exactly flat terrain

- **Decision.** On a constant surface SVF is 1 − O(1e-15), never above 1, rather than exactly 1.
- **Why.** The four bilinear weights don't sum to exactly 1 in floating point. An exact 1 would need a
  difference-form interpolation costing about 30 % more SVF time. float16 patches can't resolve the difference
  anyway: their spacing near 1 is 4.9e-4. The analytic test asserts 1 to 1e-12.

## Real-DTM integration test (gate G1)

- **Decision.** `tests/test_channels_real.py` (`@pytest.mark.needs_data`) skips unless both hold:
  - `results/provenance.json` records `gate_G1.pass == true`, following the schema in P1-03's working tree:
    `result["gate_G1"] = {"pass": ..., "failures": ...}`;
  - the DMR 5G rasters exist under the data directory.

  It reads the first raster in sorted order and checks:
  - the invalid rule and the grid alignment;
  - patch vs full ≤ 5e-9 at 12 fully valid corners plus up to 4 partially valid ones;
  - value ranges;
  - D4 on a real block to 1e-9.
- **Evidence.** P1-04 never ran it on real data. In this worktree it skips (no `provenance.json`, no `data/`). The
  code path was exercised once on a synthetic stand-in: a 700 × 600 GeoTIFF in the scratchpad with 0 m cells, and a
  temporary `{"gate_G1": {"pass": true}}` file that was deleted straight after. Result: 3 passed. If P1-03's final
  schema differs, `_gate_g1` in that file is the one place to change.
