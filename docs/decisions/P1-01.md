# P1-01 decisions: scaffold and environment

## Environment pins

- **Decision.** Python 3.13 (3.13.15 here) with uv. Every direct dependency is pinned exactly in `pyproject.toml` and
  everything is locked in `uv.lock`. PyTorch is `torch==2.14.1+cu130` with `torchvision==0.29.1+cu130` from the
  `https://download.pytorch.org/whl/cu130` index.
- **Why.** BRIEF.md Phase 1 item 1: pin exact versions; the spike used torch 2.14.1+cu130 on Python 3.13.
- **Evidence.** [E] `results/environment.json`: CUDA available on the RTX 3060 (12 GB, capability 8.6), bf16
  supported, CUDA runtime 13.0, cuDNN 9.24, driver 621.14, PROJ 9.8.1, GDAL 3.12.2.
- **Deviation?** No. The spike's torch build was available, so none was needed.

## D01 · Raw data read in place

- **Decision.** Every hand-over file is read in place from `data/raw_data/` and never copied or written. The location
  lives in `landslide.paths` (`LANDSLIDE_RAW_DIR` overrides it). The sha256 check of every file against `MANIFEST.csv`
  is P1-03's.
- **Why.** The brief allows "copy files from `raw_data/` or read them in place, but never modify `raw_data/`".
  Reading in place avoids 11 GB of duplicates.
- **Deviation?** No.

## D01a · Shared data directory for worktrees (new)

- **Decision.** `LANDSLIDE_DATA_DIR` moves the whole `data/` root. Agents working in git worktrees set it to the main
  checkout's `data/`, so all tasks read and write one data tree. Tracked outputs (`results/`, `figures/`) and `logs/`
  stay in each checkout.
- **Why.** `data/` is gitignored, so a fresh worktree has no data. One shared tree also keeps P1-08's derived files
  visible to P1-09 and later tasks.
- **Deviation?** No; infrastructure only.

## D02 · Random numbers

- **Decision.** `numpy.random.default_rng` everywhere, never the `random` module. A step with a seed from Appendix B
  uses `default_rng(seed)` where the method names the seed directly (e.g. "shuffled (seed 11)"). A step that needs a
  separate stream uses `default_rng(SeedSequence([seed, stream_id]))` through `landslide.config.rng_for(cfg, seed,
  name)`, with the stream ids registered by name in the config's `replication.streams` block (P1-02 owns it). Torch
  seeding is P1-06's.
- **Why.** Independent, reproducible streams per step: adding a draw in one step can't shift another step's numbers.
- **Deviation?** No; Appendix A fixes seeds but not generators.

## D02a · Config hash (new)

- **Decision.** `config_hash` = sha256 of the canonical JSON of `configs/landslide.json` without the top-level
  `status` key: keys sorted, separators `(",", ":")`, `ensure_ascii=False`, UTF-8. Whitespace and key order don't
  change it; any other value does.
- **Why.** Run directories and `done.json` record the hash; the runner and evaluation compare it with
  `configs/landslide.sha256` written at the freeze. `status` only records whether the config is frozen. If it were
  hashed, setting it to FROZEN would change the hash, and every file built before the freeze (splits, dataset)
  would carry a hash that never matches the frozen one. (Changed by the orchestrator on 2026-11-26, before any
  dataset was built.)
- **Consequence.** Any *other* config change after a file is built makes that file's recorded hash stale. P1-16
  rebuilds any such file under the final config and confirms its content is unchanged.

## Network client

- **Decision.** `landslide.net.Client`: User-Agent `landslide-lidar-replication
  (+https://github.com/Mark-Bugden/landslide-lidar)`, at least 0.3 s from the end of one request to the start of the
  next, up to 5 retries with exponential backoff (factor 2 s) on connection errors and HTTP 429/5xx, a hard error on
  any `outSR` parameter (in params, form data or the URL query, any case), and an allowlist of the two service hosts
  (`ags.cuzk.gov.cz`, `mapy.geology.cz`) over https. ArcGIS error bodies (HTTP 200 with `error`) raise. The ImageNet
  weights go through torchvision's own downloader (P1-07), not this client.
- **Why.** BRIEF.md "Requests" and PLAN.md §3 rule 4.

## D4 convention

- **Decision.** Transform k ∈ 0..7 is `rot90(flip_lr(x) if k ≥ 4 else x, k mod 4)` on the last two axes; numpy and
  torch give identical results (tested). TTA views are concatenated view-major.

## Smoke redirection

- **Decision.** `Paths(smoke=True)` redirects run outputs only (runs, stage 2, results, figures, logs) to
  `data/smoke/`. Inputs (raw data, caches, derived files, the dataset, baseline predictions) are shared, so the smoke
  test reads the real dataset but can never write to the tracked `results/` or `figures/`.
